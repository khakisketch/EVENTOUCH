# EVENTOUCH 맥락형 운영 셸 설계 (2026-10-04)

## 목표

상단에 동등한 무게로 늘어선 14개 화면 버튼을 다섯 업무 계층으로 재구성해, 운영자가 행사 업무 맥락을 빠르게 찾고 데스크톱·모바일 모두에서 실제 화면을 사용할 수 있게 한다.

## 설계 계약

- 기존 14개 화면 ID, 렌더러, 업무 동작, `ETKO.canRoute` 권한 검사를 유지한다.
- 내비게이션 계층은 `대행사`, `행사`, `현장`, `참가자`, `스크린`이다.
- 경로 매핑:
  - 대행사: `agency-home`, `agency-events`, `agency-clients`, `agency-team`
  - 행사: `overview`, `participants`, `engage`, `content`, `messages`, `stage`
  - 현장: `checkin`, `booth`
  - 참가자: `participant`
  - 스크린: `screen`
- 데스크톱은 고정 폭 좌측 작업 내비게이션과 본문 워크스페이스를 사용한다. 선택한 업무 계층의 세부 경로만 표시하고, 활성 경로를 `aria-current="page"`로 노출한다.
- 모바일(800px 이하)은 폭을 압박하는 좌측 레일 대신 5개 계층 선택기와 선택 계층의 가로 스크롤 가능한 세부 메뉴를 위쪽에 배치한다. 주요 내비게이션 컨트롤은 44px 이상이고 본문은 전체 폭을 사용한다.
- 활성 행사 선택은 기존 `ETKO.switchEventAndRender`를 호출한다. 샘플 저장소의 행사명 외에 새로운 행사 데이터를 만들지 않는다.
- STAFF가 접근할 수 없는 대행사 계층 등은 기존 권한 검사 결과에 따라 내비에서 숨긴다. 권한 제어 자체는 바꾸지 않는다.
- 승인 브랜드 값을 유지한다: `#F35B2C`, `#BC3F1B`, `#FAF8F5`; 기존 폰트와 Warm Operations 토큰을 재사용하고 외부 이미지·새 로고·새 팔레트를 추가하지 않는다.
- 콘텐츠 마운트와 개별 화면의 업무 UI는 그대로 두며, 이 변경은 셸·탐색·활성 행사 컨텍스트에 한정한다.

## 출처 및 참고

- 제품: `index.html` → `app.js` → `features/views.js` → 기존 화면 렌더러.

## 검증 기준

- `node --test tests/*.test.cjs` 전체 통과.
- 14개 경로가 각각 정확한 계층에 속하며, 계층 전환은 해당 계층의 접근 가능한 기본 경로로 이동한다.
- 행사 선택은 활성 행사와 화면 데이터를 함께 전환한다. 권한 거부 시 선택된 계층/현재 화면이 임의로 바뀌지 않는다.
- 1280px 데스크톱과 390px 모바일에서 가로 페이지 overflow가 없고, 세부 메뉴가 조작 가능하며, 화면 전환 후 활성 경로가 표시된다.
- 320px·768px도 레이아웃과 내비게이션 클리핑을 확인한다. 모바일 브라우저 에뮬레이션은 실제 기기 테스트로 주장하지 않는다.

## 범위 밖

- 개별 행사 화면의 업무 데이터·렌더러 개편, 새로운 인증·메시징·결제·장비 연동.
- 새로운 역할·경로 또는 저장 모델.
- 실제 provider 자격, 물리 카메라, 실제 스크린리더 청취, 종단 사용자 수락.

## 승인 상태

사용자는 기존 레이아웃이 제품 수준에 못 미친다고 지적한 뒤, 대행사·행사·현장·참가자·스크린 계층 구조와 모바일 별도 탐색 방향을 안내받고 `continue`로 구현 진행을 지시했다. 기존 브랜드 방향과 이 범위 안에서 구현한다. OpenDesign 원본 스냅샷 자체에 대한 별도 시각 만족도 판정과 제품의 최종 수락은 사용자에게 남는다.
