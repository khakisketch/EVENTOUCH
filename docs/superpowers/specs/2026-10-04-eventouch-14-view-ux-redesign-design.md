# EVENTOUCH 14개 화면 UX 재설계

> 상태: 사용자 검토용 설계 초안. 이 문서 승인은 구현·병합·배포 승인을 대신하지 않는다.

## 목표

14개 기존 화면을 처음 방문하는 관리자도 업무를 쉽게 찾고 입력 실수를 복구할 수 있도록 재구성한다. 사용자는 먼저 여러 현장을 한눈에 보고, 현장 하나를 선택한 뒤 그 현장의 준비와 당일 운영을 수행한다. 참가자용 화면과 관객 송출 화면은 운영자 도구와 분리한다.

## 사용자와 성공 기준

- 우선 사용자: 여러 EVENTOUCH 현장을 관리하는 대행사/행사 관리자.
- 중심 사용 모델: **전체 현장 홈 → 선택된 단일 현장 워크스페이스**.
- 성공 기준: 현재 선택된 현장을 항상 알 수 있고, 각 작업의 위치를 예측할 수 있으며, 형식 오류가 난 입력을 빠르게 고칠 수 있다.
- 데스크톱 관리와 모바일 현장 운영을 모두 지원한다.

## 승인된 설계 결정

1. 체크인·부스는 선택된 단일 현장 안의 `당일 운영`에 둔다. 현장별 참가자·체크인·부스·콘텐츠·메시지·참여 데이터와 팀 권한이 현재 행사 워크스페이스에 속하기 때문이다.
2. 고객사·현장 목록처럼 현장 간 공통인 관리는 전체 현장 영역에 둔다. `agency-team`은 현재 현장 구성원을 다루므로 단일 현장 영역으로 옮긴다.
3. 행사 생성의 기존 3단계 흐름은 유지하되 진행 표시, 필드 안내와 오류 복구를 개선한다.
4. 폼은 지속적으로 보이는 필드명, 의미에 맞는 입력 유형, 필드별 오류, 오류 위치로의 포커스 이동, 작성 값 보존을 공통 원칙으로 삼는다. 긴 본문은 여러 줄 입력을 제공한다.
5. 데스크톱은 맥락형 내비게이션, 모바일은 `전체 현장 → 선택 현장 → 준비/당일 운영`으로 한 단계씩 이동한다.
6. 참가자용 등록/티켓 화면과 관객 출력은 운영자 메뉴에서 구분한다. 관객 출력은 운영 셸 없이 전체 화면으로 연다.

## 범위와 보존 조건

- 기존 14개 route ID, 기능, 저장 구조, 업무 권한 검사를 유지한다. 메뉴 분류와 화면 구성은 바꿀 수 있지만 기존 데이터·작업을 삭제하거나 새 외부 연동을 추가하지 않는다.
- `ETKO.canRoute` 및 기존 행사 전환/워크스페이스 동작을 권한·데이터 기준으로 유지한다.
- 실제 SMS/알림톡 발송, 결제, 장비·카메라 서비스 연동을 새로 구현하지 않는다. 현재 샘플/시뮬레이션 경계를 유지한다.
- EVENTOUCH 제품명, 승인 브랜드 색상 `#F35B2C`, `#BC3F1B`, `#FAF8F5`, 기존 Warm Operations 토큰과 폰트를 유지한다. 새 로고나 별도 팔레트를 도입하지 않는다.
- 병합·공개 서버 반영은 별도 명시 승인 전까지 범위 밖이다.

## 정보 구조

### 전체 현장 영역

- `agency-home` → **전체 현장**: 여러 현장의 상태와 상세 워크스페이스 진입을 한곳에 둔다.
- `agency-events` → **현장 관리**: 현장 목록 및 기존 현장 생성 흐름.
- `agency-clients` → **고객사**: 여러 현장에 공통인 고객사 관리.

### 선택된 현장 워크스페이스

현장명·날짜·상태와 `전체 현장`으로 돌아가는 경로를 계속 보여준다. 현장 전환은 기존 행사 선택/전환 동작을 사용한다. 현장 메뉴는 업무 시점으로 묶는다.

- **개요:** `overview`
- **준비:** `agency-team`(팀과 권한), `participants`(참가자 명단), `content`(프로그램/공지), `messages`(메시지)
- **당일 운영:** `checkin`(체크인), `booth`(부스), `engage`(참여 진행), `stage`(무대)

`agency-team` route ID는 보존하되, 표시 위치는 고객사 공통 관리가 아니라 현재 현장 워크스페이스로 옮긴다. 실제 권한 검사는 기존 route guard가 계속 결정한다.

### 별도 사용자 표면

- `participant` → **참가 신청 / 내 티켓**: 참가자 셀프서비스로 분리하고 운영자 참가자 명단과 명칭을 구별한다.
- `screen` → **관객 화면**: 운영자 내비게이션 없이 출력 콘텐츠만 전체 화면으로 보여준다. 무대에서 여는 기존 링크/route 동작을 유지한다.

## 공통 입력 및 오류 동작

- 입력 요소는 placeholder만 필드명으로 쓰지 않는다. 라벨은 입력 중에도 보이고 필수/선택 상태와 필요한 형식 예시를 구분한다.
- 날짜·시간·이메일·전화번호·수량은 의미에 맞는 입력 유형과 모바일 키패드 힌트를 사용한다. 행사 날짜와 시간은 형식/범위를 검증한다.
- 공지·메시지 같은 긴 본문은 `textarea`에 입력한다. 현재 업무에서 요구하지 않는 새 발송/연동 기능은 추가하지 않는다.
- 오류는 문제 필드 옆에 설명하고 포커스를 해당 필드로 이동시킨다. 입력 값과 마법사 진행 상태는 재렌더링/이전 단계 이동 후에도 보존한다.
- 오류 상태는 해당 화면/폼에 한정한다. 다른 메뉴로 이동했을 때 이전 화면 오류를 새 화면에 표시하지 않는다.
- 데스크톱 폼은 관련 필드를 그룹화해 한두 열로, 모바일 폼은 한 열로 배치한다.

## 화면별 설계 초점

| 기존 화면 ID | 표시 역할 | 설계 초점 |
|---|---|---|
| `agency-home` | 전체 현장 | 현장 간 상태 파악과 상세 진입을 우선한다. |
| `agency-events` | 현장 관리 | 현장 생성/목록을 구분하고 기존 상태·진입 기능을 명확히 한다. |
| `agency-clients` | 고객사 | 고객사 입력을 명확한 라벨과 이메일 입력 형식으로 제공하고 오류를 해당 폼에 한정한다. |
| `agency-team` | 현장 준비 · 팀과 권한 | 선택된 현장 구성원을 관리하며 역할이 바꾸는 권한 범위를 계속 설명한다. |
| `overview` | 현장 개요 | 현장 맥락과 기존 결과/설정 진입을 분명히 한다. |
| `participants` | 참가자 명단 | 데스크톱 표와 모바일 카드를 동시에 보여주지 않는다. 기존 선택/상세/일괄 입장 동작은 유지한다. |
| `engage` | 참여 진행 | 투표·퀴즈·질문·추첨·설문·사진 작업을 기존 기능과 상태 중심으로 구분한다. |
| `content` | 프로그램·공지 | 프로그램 시간에 시간 입력을 사용하고 공지 본문을 여러 줄로 작성한다. |
| `messages` | 메시지 | 템플릿/캠페인 입력을 구분하고 메시지 본문을 여러 줄로 작성한다. 실제 발송 경계는 유지한다. |
| `stage` | 무대 | 기존 28개 장면을 이미 보유한 6개 그룹 메타데이터로 묶고 기존 송출 안전 확인을 유지한다. |
| `checkin` | 당일 운영 · 체크인 | 티켓 코드/스캔, 조회 결과, 입·퇴장 및 온라인/오프라인 상태를 빠르게 이해하도록 구성한다. |
| `booth` | 당일 운영 · 부스 | 직접/직원 스캔 상태와 기존 부스 관리 동작을 분명히 구분한다. |
| `participant` | 참가자 셀프서비스 | 티켓 찾기와 신규 참가 신청의 목적을 분리해 표현한다. |
| `screen` | 관객 화면 | 출력 콘텐츠에 집중하는 독립 전체 화면을 제공한다. |

## 반응형 및 입력 상태

- 데스크톱: 전체 현장 영역과 선택 현장 메뉴를 구분하고, 현장 안에서 `준비`와 `당일 운영`을 명확히 그룹화한다.
- 모바일: 현재 현장과 전체 현장 복귀를 식별 가능하게 유지하고, 메뉴를 한 단계씩 탐색한다. 자주 쓰는 체크인/부스 작업은 현장 개요에서 바로 찾을 수 있게 하되 기존 동작만 노출한다.
- 주요 버튼과 입력 타깃은 기존 최소 터치 크기 토큰을 따른다. 페이지 전체 가로 넘침이 없어야 하며 참가자 표의 가로 스크롤은 중복 카드 출력의 대안으로 쓰지 않는다.
- 스캔/조회는 기존 입력 및 지원 기능을 사용한다. 실제 카메라 동작은 본 설계에서 새로 추가하지 않는다.

## 검증 기준

1. 14개 기존 route ID가 기존 권한으로 접근 가능하고, 각 화면이 위 메뉴 역할에 한 번씩 매핑된다.
2. 전체 현장 ↔ 단일 현장 전환과 기존 행사 선택기에서 선택 현장 이름·데이터가 일치하고, 기존 행사 전환/저장 기능을 깨뜨리지 않는다.
3. 모든 이메일/날짜/시간/수량 입력과 본문 필드가 목적에 맞는 입력 UX를 제공한다. 잘못된 날짜/시간은 저장되지 않고 오류가 해당 필드에 연결되며 포커스를 복구한다.
4. 한 화면에서 생긴 오류가 다른 화면에 남지 않고, 오류/단계 전환 뒤 사용자가 작성한 값이 보존된다.
5. 참가자 명단은 데스크톱/모바일에서 한 표현만 표시하고, 선택·상세·기존 일괄 동작이 중복되지 않는다.
6. 무대에서 기존 28개 장면을 여섯 그룹으로 탐색할 수 있고 기존 안전 확인/송출 동작이 유지된다.
7. `screen` 경로는 운영 셸 없이 전체 화면으로 표시되고, 참가자 셀프서비스는 관리자 명단과 명확히 구별된다.
8. 1280px, 768px, 390px, 320px에서 실제 브라우저로 핵심 작업을 검증하고 페이지 가로 넘침, 키보드 포커스, 콘솔/네트워크 오류를 확인한다. 모바일 에뮬레이션은 실제 기기 검증이라고 표기하지 않는다.
9. 모든 변경 후 `node --test tests/*.test.cjs`와 관련 브라우저 흐름을 실행한다. 실제 발송/결제/장비 연동이 생기지 않았는지 확인한다.

## 구현 범위 밖

- 새 백엔드/API, 실제 메시지 발송, 결제, 장비 연동, 카메라 라이브러리 도입.
- 기존 14개 route 제거, 권한 정책 재정의, 데이터 구조의 별도 재설계.
- 새 로고/팔레트/브랜드 방향 및 공개 서버 병합/배포.
- 본 문서의 승인만으로 제품 코드 구현을 시작하지 않는다. 사용자 검토 후 별도 계획 및 OpenDesign 로컬 시안/검증 단계가 필요하다.
