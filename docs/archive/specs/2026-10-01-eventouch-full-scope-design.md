# EVENTOUCH 전체 범위 설계 (v1, 2026-10-01)

> 원본: `docs/행사운영플랫폼_개발기획안.pdf`(122p) + `docs/EVENTOUCH_서비스 기획 및 제안.html`(v7).
> 디자인: OpenDesign `eventouch-a82e/eventouch-operations.html`(20600라인 규모 리파인 완료, 한글·5계층·상태 전이 동작).
> 이 문서는 제품 폴더 구현의 기준이다. OD 시안과 어긋나면 이 문서+OD 시안을 기준으로 판단한다.

## 1. 계층 (메뉴를 섞지 않는다)

| 계층 | 사용자 | 책임 |
|---|---|---|
| 대행사 | 대행사 관리자 | 고객사·여러 행사·팀·전체 활동 |
| 행사 Workspace | 행사 담당자 | 선택한 행사 하나의 준비·운영·결과 |
| 현장 작업 모드 | 데스크·부스 담당자 | 입퇴장·인증 처리와 결과 복구 (별도 DB 없음) |
| 참가자 웹 | 참가자 | 일정·티켓·참여 |
| 스크린 출력 | 관객 | 공개 콘텐츠 보기 (연락처·운영 버튼 금지) |

## 2. 역할·권한

`AGENCY`(전부) > `MANAGER`(담당 행사) > `CLIENT`(조회) / `STAFF`(현장 업무만) / `VIEWER`(읽기만).
`ETKO.canRoute(role, route)`가 메뉴·직접 경로·쓰기 명령을 모두 제한한다. 프로토타입이므로 실제 인증이 아님을 표시한다.

## 3. 핵심 흐름과 상태

- 행사: 3단계 생성(기본정보→참여기능→검토) → PRE → LIVE → END. 빈 행사에는 이전 기록을 복제하지 않는다.
- 등록: 양식 설정(필수/선택·버전) → 참가 신청 → 명단 → 티켓. 중복 등록 거부, 정원 초과 거부.
- 체크인: `ETKO.scan` 7종 판정(성공/중복/미등록/다른 QR종류/다른 행사/취소자/오프라인대기). 대기는 성공이 아니다.
  오프라인은 큐 보관 후 재연결 동기화, 중복 추가 금지. 정정은 원본 삭제 없이 사유(5~200자) 필수로 최근 기록만.
- 부스: 행사당 SELF|STAFF 중 하나(기록 존재 시 변경 금지). 부스별 수량·1인당 횟수·시간·상태(OPEN/WAITING/CLOSED) 검증 후 발급.
  QR 식별자는 `ET:BOOTH:<eventId>:<boothId>` (암호화 토큰 아님).
- 참여: 투표(개시/마감·1인1표·결과 바) / 퀴즈(제출·정답 공개) / Q&A(질문→승인→무대 선택) /
  럭키드로우(시작→확정, 입장자 중 추첨) / 만족도(5점 문항·1인1회) / 사진(업로드→검토 PENDING→공개/숨김→포토월).
- 메시지: 대상 ID 고정 → 내용/템플릿 → 채널(알림톡/SMS/LMS/MMS)·예약 → 초안/예약 저장. 실제 발송 미연동(`SIMULATION_ONLY`) 표시.
- 콘텐츠: 프로그램(시간·장소) / 공지 / 행사장(약도) / 게시판(300자).
- 결과: 분석은 읽기 전용(등록/누적입장/현재입장/미입장 정의 고정). 보고서는 생성 시점 스냅샷(불변) → 미리보기 → JSON/인쇄.

## 4. 데이터 경계

- `ETKO.store = { events, workspaces, activeEventId, role }`, 행사별 workspace가 참가자·부스·기록을 소유한다.
- 출력·참가자 세션은 발급 시 eventId에 고정된다. 연락처·팀 목록을 출력 데이터에 넣지 않는다.
- 모든 쓰기는 한글 오류 메시지의 `throw Error`로 거절한다. 성공 결과는 화면·기록에 반영된다.

## 5. 전역 제약

- 사용자 문구는 한국어, `html lang="ko"`. 브랜드 `#F35B2C`, 행동 `#BC3F1B`, 배경 `#FAF8F5`.
- 주요 타깃 44px, 티켓 입력 52px, 보이는 포커스, live region 중첩 금지.
- 320/390/768/1440에서 페이지 가로 스크롤 금지(표는 래퍼 내부 스크롤).
- 실제 인증·결제·발송·장비 연결 주체 금지. 가상 역할 선택은 데모용임을 표시.

## 6. 수락 기준

역할별로 진입→처리→완료→다음 행동이 끊기지 않고, 실패 후 복구 경로가 있다.
화면 수가 아니라 위 3번 흐름이 전부 동작하는지로 판단한다. `node --test tests/*.test.cjs` 전부 통과.
