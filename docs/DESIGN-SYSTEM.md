# EVENTOUCH 디자인 시스템

Updated: 2026-10-12 · 기준 리비전: `36243c9` · 토큰 원본: `assets/css/tokens.css`

새 화면을 만들 때 이 문서대로 만든다. 값을 새로 발명하지 않는다. 여기에 없는 것이
필요하면 토큰을 먼저 추가하고 이 문서를 갱신한다.

빌드 단계가 없으므로 컴파일이 규칙을 강제하지 않는다. 대신 `npm run a11y`(12화면)와
`npm run mobile`(6기기×2방향×6화면)이 결과를 검사한다.

적용 범위: `E.*` 헬퍼·`od-*` 프리미티브·체크리스트 9절은 구 앱(바닐라) 전용이다.
새 앱(`apps/web`)은 같은 토큰 값을 자체 `tokens.css`로 옮겨 쓰고 CSS 모듈로 구현한다.
새 앱 콘솔은 확정 내비게이션 껍데기를 살리는 절충 방향을 따른다(다크 사이드바·랜드마크·
행사/고객사 메뉴). 토큰 값 자체는 바꾸지 않는다.

시각 POV: 현장 아티팩트. 범용 어드민 관용구로는 행사 제품의 특정성이 드러나지
않으므로, 설득이 필요하면 일러스트·목업 대신 실제 화면·티켓·현장 산출물을 증거로
쓴다(`apps/web/public/evidence/`, 랜딩 `실제 화면` 절). 토큰·레이아웃은 그대로 두고
증거의 선택으로 말한다. 참가자 티켓은 단일 절취선·입장 상태·여유 있는 QR로, 행사 홈은
정렬된 D-day·날짜와 상태 점이 붙은 단계 배지로 현장 흐름을 드러낸다.

## 2. 레이아웃 프리미티브 (`od-*`)

`index.html`의 `@layer od-layout`에 정의된다. **레이어가 먼저 선언되므로 제품 CSS가
항상 이긴다.** 구조만 담당하고 시각은 담당하지 않는다.

| 클래스 | 역할 |
|---|---|
| `od-stack` | 세로 흐름. 자식이 각자 한 줄 |
| `od-row` / `od-row-top` | 가로 흐름. 후자는 위 정렬 |
| `od-cluster` | 줄바꿈되는 가로 묶음(태그·버튼 무리) |
| `od-grid` | `--od-cols` 열 그리드 (기본 3) |
| `od-field` / `od-stat` / `od-cell` | **라벨·값을 세로로 쌓는 정보 단위.** 형제를 인라인으로 두지 않는다 |
| `od-fill` / `od-fixed` | 남는 공간 차지 / 고정 |
| `od-media` / `od-media-cover` | 비율 유지 / 크롭(명시적 선택) |
| `od-scroll` / `od-screen` | 스크롤 영역 / 화면 골격 |
| `od-rail` | 가로 스크롤 목록(다음 항목이 가장자리에 보임) |
| `od-truncate` / `od-clamp-2` / `od-clamp-3` | **데이터 텍스트만.** 문장은 문구를 줄인다 |
| `od-nowrap` | 숫자+단위, 가격+기 등 붙어 있어야 하는 것 |
| `od-touch` | 44px 최소 터치 영역 |

핵심 규칙: **`od-field`류는 각 조각을 자기 줄에 둔다.** `<span>`을 형제로 나열해
가로로 붙이는 것이 이 제품에서 반복된 실수였다.

## 3. 컴포넌트

마크업은 문자열 헬퍼로 만든다(`E.*`). 괄호는 실제 호출 수(2026-10-12 기준).

### 컨테이너

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.head(제목, 설명, 액션, eyebrow, 클래스)` | 화면 머리. 모든 화면이 이걸로 시작 | 40 |
| `E.panel(제목, 내용, 머리 오른쪽)` | 내용 묶음. 기본 표면 | 65 |
| `E.detail([[라벨, 값], …])` | 라벨·값 목록. 상세 정보 | 32 |
| `E.table(머리[], 행[])` | 표. 50행씩 페이지, 모바일에서 카드로 전환 | 28 |
| `E.stats([[숫자, 라벨, 단위], …])` | 지표 묶음 | 3 |

### 피드백 — 네 가지를 구분해서 쓴다

| 헬퍼 | 언제 | 호출 |
|---|---|---|
| `E.notice(문구, 'warning'\|'error'\|'good')` | **화면 안에 남는 설명.** 기능 미연동, 정책 안내 | 108 |
| `E.toast(문구)` | **잠깐 사라지는 결과 알림.** 저장 완료 | 56 |
| `E.dialog(제목, 내용, 콜백, 버튼, 넓게)` | 입력을 받는 모달. 폼이면 `callback`을 준다 | 62 |
| `E.empty(제목, 설명, 행동)` | **데이터가 없을 때.** 점선 테두리 | 49 |

`notice`를 토스트 대신 쓰지 않는다(사라지는 정보와 남는 정보는 다르다). 반대로 저장
결과를 `notice`로 남기지 않는다.

### 표시

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.badge(글자, 'good'\|'warn'\|'bad')` | 상태 라벨. 색은 상태 의미에 맞춘다 | 35 |
| `E.icon(이름)` | 인라인 SVG. 크기 20px 고정 | 33 |
| `E.image(파일, 대체텍스트)` | 이미지. 비율 유지 | 12 |

### 행동

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.button(라벨, action, 속성, 종류, 아이콘)` | `data-action` 버튼. `primary`는 화면당 하나 | 13 |
| `E.link(라벨, href, 종류, 아이콘)` | 이동 | 9 |
| `E.submit(라벨)` | 폼 제출 | 20 |

**한 화면에 `primary`는 하나.** 체크인 화면에서 스캔과 티켓 제출이 둘 다 주황이었던
것을 리뷰에서 지적받아 제출을 보조로 낮췄다.

### 폼

`E.field(라벨, name, 값, 타입, 속성)` · `E.select(라벨, name, 선택지, 값)` ·
`E.check(라벨, name, 체크, 값)`

폼은 `data-form="이름"`으로 표시하고 `E.forms['이름']`에 처리 함수를 등록한다.
`novalidate`를 붙이고 검증은 `E.validateInput`이 담당한다. 오류는 `role="alert"`인
`.error-summary`와 필드별 `.field-error`(`aria-live`)에 쓴다.

### 전화번호·수량 입력

`inputmode`와 `autocomplete`를 지정한다. 금액·수량은 `inputmode="numeric"`.

## 4. 상태 표현 규칙

빈 상태·오류·로딩을 **각각 다르게** 표현한다.

- **빈 상태**: `E.empty`. 왜 비었는지 + 다음 행동을 준다. 권한 때문에 걸러진 경우와
  진짜 0건을 구분해서 쓴다(과거에 "결과 없음"을 권한 문제에도 쓰는 결함이 있었다).
- **오류**: `E.notice(…, 'error')` 또는 폼이면 `.error-summary`. 런타임 실패는
  `#runtime-error` 박스.
- **연결 상태**: `server-presentation.js`의 `connectionNotice()`. 서버 모드에서만.
- **로딩**: `.skeleton` + `role="status"`.
- **오프라인**: 인터넷이 끊기면 `offlineGuidance()`가 무엇이 되고 안 되는지 알린다.

상태 라벨은 한국어로 쓴다. 원시 키(`SENDING`, `PARTIAL`)를 화면에 노출하지 않는다 —
`E.messageStatuses`, `E.deliveryStates`, `E.registrationStates` 같은 매핑을 거친다.

## 5. 반응형

실제로 쓰이는 `@media` 구간은 다음과 같다(측정값).

**주요 구간 — 여기만 기억하면 된다**

| 구간 | 규칙 |
|---|---|
| `≤768px` | 페이지 머리 세로 배치, 폼 1열, 패널 여백 `--s4`, **표 → 카드 전환**, 탭 가로 스크롤. CSS에서 14회로 가장 많이 쓰인다 |
| `≤1024px` | `split` 1열, 지표 2열 |
| `≥769px` | 토스트가 우측 상단 칩 |

**미세 조정 구간** — 특정 기기 폭에 맞춘 것들이다. 새 화면을 만들 때 기준으로 삼지 않는다.

    max-width:  350 · 360 · 375 · 380 · 420 · 480 · 520 · 700 · 760
    min-width:  768 · 769 · 900 · 1440

구간이 열한 개로 흩어져 있는 것은 일관성 부채다. 새 규칙은 768/1024에 붙이고,
미세 구간을 늘리지 않는다.

**터치 타깃 최소 44px.** `npm run mobile`이 위반을 잡는다.
표는 데스크톱에서 `<table>`, 모바일에서 `data-label`을 이용한 카드가 된다 —
`.table-scroll` 안에 두면 자동이다.

## 6. 접근성

- 포커스: `outline: 3px solid var(--focus)`, `outline-offset: 3px`. 모든 상호작용 요소.
- 모달: `role="dialog"`, `aria-modal`, `aria-labelledby`, 열 때 첫 요소 포커스,
  Escape 닫기, 닫을 때 이전 포커스 복귀.
- 토스트: `role="status"` + `aria-live="polite"`. 오류 요약은 `role="alert"`.
- 라벨 없는 입력을 만들지 않는다. 아이콘만 있는 버튼은 `aria-label` 필수.
- 색만으로 의미를 전달하지 않는다 — 배지에 글자가 함께 있다.
- `prefers-reduced-motion`이면 전환·애니메이션을 끈다.
- 건너뛰기 링크(`.skip`)가 첫 요소다.

## 7. 인쇄

`@media print`에서 사이드바·툴바·탭·토스트·모달을 숨기고 본문만 남긴다. 표는
카드가 아니라 표로 되돌린다. `.print-only`, `.no-print`로 제어한다.
보고서는 `E.printContent()` → 브라우저 인쇄 → PDF 저장 경로를 쓴다.

## 8. 알려진 불일치 (측정값)

새 화면을 만들기 전에 알아야 할 것들이다. 고칠 대상이지 따를 패턴이 아니다.

- **폼 필드 헬퍼 사용률이 낮다.** `E.field` 호출 7회 vs 원시 `<input>` 20회.
  결과적으로 라벨·오류 연결이 화면마다 다르다. 새 화면은 `E.field`를 쓴다.
- **폼 등록 방식이 두 가지다.** `E.forms['이름']` 20회 vs `E.forms.이름` 6회.
  동작은 같지만 검색이 안 된다. 괄호 표기로 통일한다.
- **뷰 10개·액션 16개가 중복 정의**된다(로드 순서로 뒤가 이김). 자세한 목록은
  `docs/ARCHITECTURE.md` 7절. 고칠 때 어느 정의가 이기는지 먼저 확인한다.
- **사용되지 않는 프리미티브 6종**: `od-grid`, `od-cluster`, `od-rail`,
  `od-row-top`, `od-truncate`, `od-touch` — 정의만 있고 호출이 0회다. 삭제 후보지만
  `od-touch`(44px 보장)는 앞으로 쓸 값이 있으므로 남길지 판단이 필요하다.
  반대로 `od-field`는 89회로 폼·정보 단위의 사실상 표준이다.
- `--report-color`, `--chart`, `--chart-track`, `--phone-*`은 특정 화면 전용이다.

## 9. 새 화면 체크리스트

1. `E.head`로 시작하고 화면 목적을 한 줄로 쓴다.
2. 내용은 `E.panel`로 묶고, 상세는 `E.detail`, 목록은 `E.table`.
3. 상태는 `empty` / `notice` / `toast` / `badge` 중 의미에 맞는 것을 쓴다.
4. 입력은 `E.field`·`E.select`·`E.check` + `E.forms[...]`.
5. `primary` 버튼은 하나.
6. 하드코딩 색·간격을 쓰지 않는다. 토큰만.
7. 320/390/768/1024/1280에서 확인한다.
8. `npm test`, `npm run a11y`, `npm run mobile`을 돌린다.
9. 중복 정의되는 이름을 피하거나, 피할 수 없으면 어느 것이 이기는지 주석으로 남긴다.

## 9. 새 앱 콘솔 페이지 구성(2026-10-16)

적용 범위는 Next.js 새 앱 `apps/web/app/console/**`다. 위 구 앱 체크리스트와 `E.*`·`od-*`
규칙은 이관이 끝날 때까지 그대로 보존한다. 새 콘솔 페이지는 아래 세 부품을 조합해 페이지
머리·섹션 제목·초기 상태 표현을 한 곳에서 유지한다. 한 화면마다 다른 제목 크기, 뒤로가기 위치,
오류 복구 모양이 생기면 행사 탐색과 작업 우선순위를 비교하기 어렵기 때문에 표현을 중앙화한다.

### `ConsolePageHeader`

순서는 고정한다: 선택적 `back` → 32px `h1` → 행사 메타 한 줄 → 선택적 배지 → 우측 보조 액션.
행사 하위 페이지의 제목은 행사명이고, 최상위 페이지는 페이지명이다. 메타는 고객사 · 날짜 · 시간 ·
장소 순서이며 값이 없는 항목은 생략한다. 행사 하위 페이지는 `← 운영 현황` 뒤로가기를 이 머리에
둔다. 운영 현황 자신은 뒤로가기를 두지 않는다. 셸 하위내비가 페이지 이름을 표시하므로 eyebrow는
콘솔 어디에도 두지 않는다. 헤더 액션은 이동·보조 작업뿐이며 `button-secondary`를 사용한다.

| prop | 용도 |
|---|---|
| `title: string` | `h1` 제목 |
| `back?: { href, label }` | 컴팩트 뒤로가기 링크 |
| `meta?: ReactNode` | 고객사·일정·장소 정보. 행사 메타는 `formatConsoleEventMeta`로 정규화 |
| `badges?: ReactNode` | 운영 현황의 단계·접수·일정 배지 |
| `actions?: ReactNode` | 우측 보조 액션. 주황 primary 금지 |
| `className?: string` | 기존 화면 구조의 국소적인 배치 보존 |

뒤로가기 링크는 DOM·키보드 순서상 제목과 메타, 헤더 액션보다 먼저 온다. 공통 CSS는 제목 32px,
메타 글자·간격, 헤더 하단선을 제공한다. 좁은 폭에서는 정보와 액션을 세로로 쌓고 44px 버튼 크기를
전역 규칙에 맡긴다.

### `ConsoleSection`

페이지의 각 의미 단위는 이 부품으로 묶는다. 제목은 `h2`, 설명은 선택적 보조 문장, 액션은 선택적
보조 액션이다. 컴포넌트가 `headingId`를 `h2 id`와 `section aria-labelledby`에 함께 연결한다.
운영 현황에서 가져온 기준은 제목 `--h3`(20px), 줄 높이 1.35, 설명 `--small`(14px), 제목-설명
간격 `--s1`, 섹션 간 기본 간격 `--s3`다. `density="compact"`는 짧고 응집된 목록에만 제한하고,
주의 항목을 새 카드 스트립으로 늘리지 않는다. 카드 배경·경계는 해당 작업 영역이 이미 가진 표현을
`className`으로 유지할 수 있다.

| prop | 용도 |
|---|---|
| `headingId: string` · `title: string` | 접근성 이름과 섹션 제목 |
| `description?: ReactNode` | 제목 아래 보조 설명 |
| `action?: ReactNode` | 보조 액션만. 주황 primary 금지 |
| `children: ReactNode` | 섹션 본문 |
| `className?: string` | 기존 카드/그리드 배치 보존 |
| `density?: "default" \| "compact"` | 기본 간격 또는 확인 필요처럼 압축된 밀도 |
| `divider?: boolean` | 기존 패널 헤더의 아래 구분선 유지 |

### `ConsoleStatePanel`

초기 로딩은 `role="status"`와 “...를 불러오고 있습니다.” 문구를 쓴다. 실패는 `role="alert"`와
보조 `다시 불러오기` 버튼을 제공한다. 버튼은 `eventouch:shell-reload`를 dispatch한 뒤 페이지의
기존 재조회 함수를 호출한다. 선택적 `actions`는 가져오기 같은 단계 흐름의 복귀 경로를 유지할 때만
사용한다. 각 페이지는 데이터·권한 판단과 재조회 동작을 소유하고, 부품은 상태 표현만 공유한다.

| prop | 용도 |
|---|---|
| `kind: "loading" \| "failed"` | 초기 상태 종류 |
| `message: string` | 상태별 한국어 안내. 로딩 문구는 반드시 “불러오고 있습니다.”로 끝낸다 |
| `onRetry: () => void` | 실패 재조회. 로딩에서는 호출되지 않는다 |
| `actions?: ReactNode` | 실패 복구 뒤의 선택적 흐름 이동 |

### 운영 현황 지표

- `DRAFT`·`READY`는 신청 · 참가 확정 · 승인 대기를 하나의 압축 수치 행으로 읽고, 정원이 설정되면
  대기/정원을, 정원 0(제한 없음)이면 그 상태를 명시한다. 같은 크기의 네 지표 카드 그리드는 쓰지 않는다.
- `LIVE`·`ENDED`는 입장 진행 바를 중심에 둔다. 취소를 제외한 전체 등록 수가 분모이며, 눈에 보이는
  `입장/등록명 · 백분율`과 `role="progressbar"`의 `aria-label`·값을 함께 제공한다. 입장률 정의는
  결과 보고서와 같다. 확정자 중 미입장은 별도의 참가자 드릴다운으로 둔다.
- `ENDED`는 설문 응답·보고서 상태만 작은 보조 정보로 보여준다. `ARCHIVED`는 최종 요약이며 읽기 전용이다.
  참가자·보고서 상세 링크는 기존 목적지로 이동한다.
- 확인 필요 스트립과 운영 준비 블록은 운영 현황에 두지 않는다. 확인 건수는 셸의 행사 하위 메뉴로
  연결하고, 데스크·부스 설정은 현장 운영 화면에서 확인한다.

### 셸 메뉴 배지

- 현재 행사 `참가자` 메뉴는 `PENDING` 수, `메시지` 메뉴는 `FAILED`·`PARTIAL`·`NEEDS_CONNECTION`
  캠페인 수를 표시한다. 숫자·색·접근 가능한 이름(`승인 대기 N건`, `발송 확인 N건`)을 함께 쓴다.
- `AGENCY`·`MANAGER`에만 표시한다. 이것은 내비게이션의 표시 게이트일 뿐 서버 권한을 대체하지 않는다.
  `ENDED`·`ARCHIVED`에서는 승인 배지를 숨기고 메시지 배지는 유지한다. 대기가 있으면 참가자 링크가
  `?status=PENDING`으로 바로 들어간다. 메시지 배지는 `?attention=1`로 확인 대상 캠페인만 보여주고
  이력 섹션으로 이동한다. 이 화면에는 전체 캠페인으로 돌아가는 동작을 함께 둔다.
- 데스크톱 사이드바와 모바일 행사 메뉴는 같은 하위 메뉴 렌더 함수를 써 배지 규칙을 공유한다.

### 단계 이동과 새로고침

- 단계 전환은 행사 설정에서만 제공한다. 인라인 확인, 전제조건 안내, 알 수 없는 단계·보관 단계의
  읽기 전용 처리를 유지하고, `event.stage` 커맨드의 응답이 불확실한 재시도는 같은 `commandId`를 쓴다.
  최종 권한·단계 판정은 계속 서버가 한다.
- 최근 입퇴장 새로고침은 20px SVG 아이콘과 44px 이상 버튼을 쓴다. `aria-label`·`title`은
  `새로고침`, 진행 중에는 `aria-busy`와 회전을 표시하고 `prefers-reduced-motion`에서는 회전을 끈다.
  “마지막 갱신 HH:MM”과 오류 복구의 “다시 불러오기”는 유지한다.

### 포토월과 행사 증빙 사진

- 참가자 포토월 게시물과 행사 증빙 원본은 목적·공개 범위가 다르므로 별도 화면/데이터로 보여준다.
  기존 프로그램 안의 참가자 사진은 검토 흐름을 유지하고 ZIP에는 승인된 사진만 포함한다.
- 행사 증빙 사진은 제안서의 고정 8개 분류를 선택하는 운영자 화면으로 관리한다. 모든 섹션을 한 번에
  펼치지 말고, 분류별 사진 수와 현재 선택 섹션을 함께 보여준다. ZIP은 선택한 섹션만 담는다.
- `AGENCY`와 해당 행사 MANAGER에게만 업로드·이동·보관함 제거 UI를 보인다. 제거는 보관함 참조만 빼며
  저장 파일 삭제나 기존 행사 파일 읽기 권한 회수가 아니라는 점을 확인 단계에서 설명한다. 서버 권한은 매 파일 요청·커맨드마다 판정한다.

### 버튼·뒤로가기 규율과 완료 범위

헤더와 섹션 머리 액션 슬롯에는 보조 스타일만 둔다. 화면의 핵심 작업을 슬롯 규칙에 맞추려고
보조화하지 않는다. 핵심 primary는 본문 작업 흐름에 남긴다. 운영 현황은 primary 0개를 유지한다.
행사 하위 페이지의 공통 뒤로가기는 `← 운영 현황` 하나이며, 중복된 하단·헤더 이동을 두지 않는다.
단계형 흐름(예: 참여 프로그램의 오류 복귀)은 필요한 복귀 목적지를 보존할 수 있다. 메타는 기존
부트스트랩 데이터만 읽고 API 계약을 확장하지 않는다.

- 행사 하위 페이지는 `h1=행사명`과 고객사 · 날짜 · 시간 · 장소 메타를 공통 헤더에 둔다. 로딩·실패
  중에도 헤더를 유지한다. 아직 행사명을 얻지 못하면 `행사`를 표시하고, 메타는 받은 값만 노출한다.
- 현장 운영은 데스크·부스·인증 방식·지도·전광판·스태프 배정의 6개 섹션을 유지한다. 데스크·부스
  추가는 섹션 보조 액션이고 `스태프 배정` primary는 본문에서 유지한다. 지도 저장·전광판 적용 등
  기존 주 작업과 상태·전제조건도 그대로 둔다.
- 참여 프로그램은 프로그램 목록을 하나의 `ConsoleSection`으로 묶고, 편집/진행 상태와 데이터 잠금,
  추첨·Q&A 검증을 보존한다. 오류의 `행사 목록으로` 복귀와 `행사 설정` 보조 이동을 유지하되 운영
  현황 중복 이동은 제거한다.
- 경품은 목록을 섹션화하고 참가자 이동을 공통 헤더의 보조 액션으로 둔다. 기능 꺼짐, 지급·취소
  상태 gate와 기프티콘 모의 안내를 보존한다.
- 결과 보고서는 분석·보고서·조건부 상세의 3개 의미 섹션을 사용한다. 생성 primary와 스냅샷·공유
  잠금·후속 버전·JSON/인쇄는 본문에서 유지한다. 모바일 표는 모든 열을 보존하고, 필요할 때만
  가로 스크롤되는 키보드 포커스 영역 안에 둔다. 인쇄 산출물의 `EVENTOUCH · 결과 보고서` eyebrow는
  콘솔 장식이 아니라 출력물 내용이므로 유지한다.
- 설정은 기존 기본 정보·기능·접수·참가자 페이지를 보존하고 `진행 단계`를 기본 정보 바로 뒤에 둔다.
  단계 확인·전제조건·불확실한 응답의 같은 `commandId` 재시도도 유지한다.
- 최상위 화면은 페이지명 `h1`만 사용하고 행사 메타·행사 뒤로가기를 두지 않는다. 콘솔 홈의
  `새 행사 만들기`는 primary로 유지하되 헤더 액션 슬롯 밖에 둔다. 행사 디렉터리 검색·단계/대기 필터·
  카드/달력과 빈 상태는 하나의 `ConsoleSection` 안에 둔다.
- 고객사는 페이지 제목과 별도 `고객사 목록` 섹션을 둔다. 업체명은 `h3`로 섹션 제목과 계층을 나누고,
  기존 목록·행 스타일의 소유자인 `globals.css`는 해당 제목 선택자만 넓힌다. 등록·업로드·삭제 확인과
  AGENCY gate를 유지한다.
- 팀은 대기 초대·구성원·연동·최근 활동·로그인 보호를 구분한다. 초대/구성원 빈 상태를 실제 목록과
  분리하고, 조직 권한·1회 노출 링크·초대 회수·비밀번호 재설정·부분 읽기 전용 패널은 유지한다.
  공용 실패 재시도는 페이지와 셸을 함께 깨운다. bootstrap 실패를 빈 구성원 목록으로 오인하지 않는다.

**1·2단계 이관 범위:** 운영 현황·참가자·가져오기·콘텐츠·메시지에 이어 `events/[id]/operations`,
`programs`, `rewards`, `reports`, `settings`, 콘솔 홈(`ConsoleHome`), `clients`, `team`까지 공통
헤더·섹션·초기 상태 구성을 적용했다. 공개 행사·참가자 화면, 스태프, 전광판은 범위 밖이다.
