# EVENTOUCH 디자인 시스템

Updated: 2026-10-12 · 기준 리비전: `36243c9` · 토큰 원본: `assets/css/tokens.css`

새 화면을 만들 때 이 문서대로 만든다. 값을 새로 발명하지 않는다. 여기에 없는 것이
필요하면 토큰을 먼저 추가하고 이 문서를 갱신한다.

빌드 단계가 없으므로 컴파일이 규칙을 강제하지 않는다. 대신 `npm run a11y`(12화면)와
`npm run mobile`(6기기×2방향×6화면)이 결과를 검사한다.

적용 범위: `E.*` 헬퍼·`od-*` 프리미티브·체크리스트 9절은 구 앱(바닐라) 전용이다.
새 앱(`apps/web`)은 같은 토큰 값을 자체 `tokens.css`로 옮겨 쓰고 CSS 모듈로 구현한다.
새 앱 콘솔은 확정 내비게이션 껍데기를 살리는 절충 방향을 따른다(다크 사이드바·랜드마크·
행사/고객사 메뉴). 토큰 값 자체는 바꾸지 않는다.

시각 POV: 현장 아티팩트. 범용 어드민 관용구로는 행사 제품의 특정성이 드러나지
않으므로, 설득이 필요하면 일러스트·목업 대신 실제 화면·티켓·현장 산출물을 증거로
쓴다(`apps/web/public/evidence/`, 랜딩 `실제 화면` 절). 토큰·레이아웃은 그대로 두고
증거의 선택으로 말한다.

## 2. 레이아웃 프리미티브 (`od-*`)

`index.html`의 `@layer od-layout`에 정의된다. **레이어가 먼저 선언되므로 제품 CSS가
항상 이긴다.** 구조만 담당하고 시각은 담당하지 않는다.

| 클래스 | 역할 |
|---|---|
| `od-stack` | 세로 흐름. 자식이 각자 한 줄 |
| `od-row` / `od-row-top` | 가로 흐름. 후자는 위 정렬 |
| `od-cluster` | 줄바꿈되는 가로 묶음(태그·버튼 무리) |
| `od-grid` | `--od-cols` 열 그리드 (기본 3) |
| `od-field` / `od-stat` / `od-cell` | **라벨·값을 세로로 쌓는 정보 단위.** 형제를 인라인으로 두지 않는다 |
| `od-fill` / `od-fixed` | 남는 공간 차지 / 고정 |
| `od-media` / `od-media-cover` | 비율 유지 / 크롭(명시적 선택) |
| `od-scroll` / `od-screen` | 스크롤 영역 / 화면 골격 |
| `od-rail` | 가로 스크롤 목록(다음 항목이 가장자리에 보임) |
| `od-truncate` / `od-clamp-2` / `od-clamp-3` | **데이터 텍스트만.** 문장은 문구를 줄인다 |
| `od-nowrap` | 숫자+단위, 가격+기 등 붙어 있어야 하는 것 |
| `od-touch` | 44px 최소 터치 영역 |

핵심 규칙: **`od-field`류는 각 조각을 자기 줄에 둔다.** `<span>`을 형제로 나열해
가로로 붙이는 것이 이 제품에서 반복된 실수였다.

## 3. 컴포넌트

마크업은 문자열 헬퍼로 만든다(`E.*`). 괄호는 실제 호출 수(2026-10-12 기준).

### 컨테이너

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.head(제목, 설명, 액션, eyebrow, 클래스)` | 화면 머리. 모든 화면이 이걸로 시작 | 40 |
| `E.panel(제목, 내용, 머리 오른쪽)` | 내용 묶음. 기본 표면 | 65 |
| `E.detail([[라벨, 값], …])` | 라벨·값 목록. 상세 정보 | 32 |
| `E.table(머리[], 행[])` | 표. 50행씩 페이지, 모바일에서 카드로 전환 | 28 |
| `E.stats([[숫자, 라벨, 단위], …])` | 지표 묶음 | 3 |

### 피드백 — 네 가지를 구분해서 쓴다

| 헬퍼 | 언제 | 호출 |
|---|---|---|
| `E.notice(문구, 'warning'\|'error'\|'good')` | **화면 안에 남는 설명.** 기능 미연동, 정책 안내 | 108 |
| `E.toast(문구)` | **잠깐 사라지는 결과 알림.** 저장 완료 | 56 |
| `E.dialog(제목, 내용, 콜백, 버튼, 넓게)` | 입력을 받는 모달. 폼이면 `callback`을 준다 | 62 |
| `E.empty(제목, 설명, 행동)` | **데이터가 없을 때.** 점선 테두리 | 49 |

`notice`를 토스트 대신 쓰지 않는다(사라지는 정보와 남는 정보는 다르다). 반대로 저장
결과를 `notice`로 남기지 않는다.

### 표시

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.badge(글자, 'good'\|'warn'\|'bad')` | 상태 라벨. 색은 상태 의미에 맞춘다 | 35 |
| `E.icon(이름)` | 인라인 SVG. 크기 20px 고정 | 33 |
| `E.image(파일, 대체텍스트)` | 이미지. 비율 유지 | 12 |

### 행동

| 헬퍼 | 용도 | 호출 |
|---|---|---|
| `E.button(라벨, action, 속성, 종류, 아이콘)` | `data-action` 버튼. `primary`는 화면당 하나 | 13 |
| `E.link(라벨, href, 종류, 아이콘)` | 이동 | 9 |
| `E.submit(라벨)` | 폼 제출 | 20 |

**한 화면에 `primary`는 하나.** 체크인 화면에서 스캔과 티켓 제출이 둘 다 주황이었던
것을 리뷰에서 지적받아 제출을 보조로 낮췄다.

### 폼

`E.field(라벨, name, 값, 타입, 속성)` · `E.select(라벨, name, 선택지, 값)` ·
`E.check(라벨, name, 체크, 값)`

폼은 `data-form="이름"`으로 표시하고 `E.forms['이름']`에 처리 함수를 등록한다.
`novalidate`를 붙이고 검증은 `E.validateInput`이 담당한다. 오류는 `role="alert"`인
`.error-summary`와 필드별 `.field-error`(`aria-live`)에 쓴다.

### 전화번호·수량 입력

`inputmode`와 `autocomplete`를 지정한다. 금액·수량은 `inputmode="numeric"`.

## 4. 상태 표현 규칙

빈 상태·오류·로딩을 **각각 다르게** 표현한다.

- **빈 상태**: `E.empty`. 왜 비었는지 + 다음 행동을 준다. 권한 때문에 걸러진 경우와
  진짜 0건을 구분해서 쓴다(과거에 "결과 없음"을 권한 문제에도 쓰는 결함이 있었다).
- **오류**: `E.notice(…, 'error')` 또는 폼이면 `.error-summary`. 런타임 실패는
  `#runtime-error` 박스.
- **연결 상태**: `server-presentation.js`의 `connectionNotice()`. 서버 모드에서만.
- **로딩**: `.skeleton` + `role="status"`.
- **오프라인**: 인터넷이 끊기면 `offlineGuidance()`가 무엇이 되고 안 되는지 알린다.

상태 라벨은 한국어로 쓴다. 원시 키(`SENDING`, `PARTIAL`)를 화면에 노출하지 않는다 —
`E.messageStatuses`, `E.deliveryStates`, `E.registrationStates` 같은 매핑을 거친다.

## 5. 반응형

실제로 쓰이는 `@media` 구간은 다음과 같다(측정값).

**주요 구간 — 여기만 기억하면 된다**

| 구간 | 규칙 |
|---|---|
| `≤768px` | 페이지 머리 세로 배치, 폼 1열, 패널 여백 `--s4`, **표 → 카드 전환**, 탭 가로 스크롤. CSS에서 14회로 가장 많이 쓰인다 |
| `≤1024px` | `split` 1열, 지표 2열 |
| `≥769px` | 토스트가 우측 상단 칩 |

**미세 조정 구간** — 특정 기기 폭에 맞춘 것들이다. 새 화면을 만들 때 기준으로 삼지 않는다.

    max-width:  350 · 360 · 375 · 380 · 420 · 480 · 520 · 700 · 760
    min-width:  768 · 769 · 900 · 1440

구간이 열한 개로 흩어져 있는 것은 일관성 부채다. 새 규칙은 768/1024에 붙이고,
미세 구간을 늘리지 않는다.

**터치 타깃 최소 44px.** `npm run mobile`이 위반을 잡는다.
표는 데스크톱에서 `<table>`, 모바일에서 `data-label`을 이용한 카드가 된다 —
`.table-scroll` 안에 두면 자동이다.

## 6. 접근성

- 포커스: `outline: 3px solid var(--focus)`, `outline-offset: 3px`. 모든 상호작용 요소.
- 모달: `role="dialog"`, `aria-modal`, `aria-labelledby`, 열 때 첫 요소 포커스,
  Escape 닫기, 닫을 때 이전 포커스 복귀.
- 토스트: `role="status"` + `aria-live="polite"`. 오류 요약은 `role="alert"`.
- 라벨 없는 입력을 만들지 않는다. 아이콘만 있는 버튼은 `aria-label` 필수.
- 색만으로 의미를 전달하지 않는다 — 배지에 글자가 함께 있다.
- `prefers-reduced-motion`이면 전환·애니메이션을 끈다.
- 건너뛰기 링크(`.skip`)가 첫 요소다.

## 7. 인쇄

`@media print`에서 사이드바·툴바·탭·토스트·모달을 숨기고 본문만 남긴다. 표는
카드가 아니라 표로 되돌린다. `.print-only`, `.no-print`로 제어한다.
보고서는 `E.printContent()` → 브라우저 인쇄 → PDF 저장 경로를 쓴다.

## 8. 알려진 불일치 (측정값)

새 화면을 만들기 전에 알아야 할 것들이다. 고칠 대상이지 따를 패턴이 아니다.

- **폼 필드 헬퍼 사용률이 낮다.** `E.field` 호출 7회 vs 원시 `<input>` 20회.
  결과적으로 라벨·오류 연결이 화면마다 다르다. 새 화면은 `E.field`를 쓴다.
- **폼 등록 방식이 두 가지다.** `E.forms['이름']` 20회 vs `E.forms.이름` 6회.
  동작은 같지만 검색이 안 된다. 괄호 표기로 통일한다.
- **뷰 10개·액션 16개가 중복 정의**된다(로드 순서로 뒤가 이김). 자세한 목록은
  `docs/ARCHITECTURE.md` 7절. 고칠 때 어느 정의가 이기는지 먼저 확인한다.
- **사용되지 않는 프리미티브 6종**: `od-grid`, `od-cluster`, `od-rail`,
  `od-row-top`, `od-truncate`, `od-touch` — 정의만 있고 호출이 0회다. 삭제 후보지만
  `od-touch`(44px 보장)는 앞으로 쓸 값이 있으므로 남길지 판단이 필요하다.
  반대로 `od-field`는 89회로 폼·정보 단위의 사실상 표준이다.
- `--report-color`, `--chart`, `--chart-track`, `--phone-*`은 특정 화면 전용이다.

## 9. 새 화면 체크리스트

1. `E.head`로 시작하고 화면 목적을 한 줄로 쓴다.
2. 내용은 `E.panel`로 묶고, 상세는 `E.detail`, 목록은 `E.table`.
3. 상태는 `empty` / `notice` / `toast` / `badge` 중 의미에 맞는 것을 쓴다.
4. 입력은 `E.field`·`E.select`·`E.check` + `E.forms[...]`.
5. `primary` 버튼은 하나.
6. 하드코딩 색·간격을 쓰지 않는다. 토큰만.
7. 320/390/768/1024/1280에서 확인한다.
8. `npm test`, `npm run a11y`, `npm run mobile`을 돌린다.
9. 중복 정의되는 이름을 피하거나, 피할 수 없으면 어느 것이 이기는지 주석으로 남긴다.
