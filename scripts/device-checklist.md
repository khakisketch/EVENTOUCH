# 물리 기기 확인 목록

`npm run mobile`은 새 앱의 실제 경로(`/`, `/event/:slug/home`, `/event/:slug/register`,
`/screen/:slug`, `/staff/events/:eventId`, `/console/events/:eventId/participants`)를
6개 실기기 프로필 × 가로/세로로 자동 검사한다. 오버플로, 44px 미만 조작 요소,
런타임 오류를 잡는다.

**그것으로 확인되지 않는 것**이 아래 목록이다. 브라우저 에뮬레이션은 실제
기기를 대신하지 못한다. 자동 검사가 통과해도 아래 항목은 별도로 확인해야
하며, 확인 전에는 "실기기 검증 완료"라고 말하지 않는다.

## 왜 자동 검사로 부족한가

에뮬레이션은 다음을 관찰할 수 없다.

- 실제 터치 입력 (손가락 크기, 오탭, 스크롤 관성)
- iOS Safari와 Android Chrome의 실제 렌더링·주소창 높이 변화
- 카메라 권한 대화상자와 실제 QR 인식률
- 소프트 키보드가 열렸을 때의 화면 밀림
- 실제 네트워크 전환 (LTE ↔ Wi-Fi ↔ 없음)
- 발열·배터리·메모리 압박

## 현장 스태프 (가장 중요)

행사 당일 이 사람이 막히면 행사가 막힌다. 우선순위 최상. 대상 화면은
`/staff/events/:eventId`다.

- [ ] **카메라 권한**: 티켓 QR 스캔 시 권한 요청이 뜨고, 허용 후 스캔된다.
      거부했을 때 코드 직접 입력으로 안내되는지도 확인.
- [ ] **화면 잠금 후 복귀**: 기기를 잠갔다 켰을 때 세션이 유지되고 체크인
      화면이 그대로인지.
- [ ] **소프트 키보드**: 티켓 코드 입력 시 키보드가 스캔 버튼이나 결과를
      가리지 않는지.
- [ ] **한 손 조작**: 스캔 → 확인 흐름을 한 손으로 완료할 수 있는지.
- [ ] **직사광선**: 야외 데스크에서 화면이 읽히는지 (밝기 최대).
- [ ] **장갑**: 장갑 낀 손으로 탭이 되는지.
- [ ] **연속 처리 100건**: 스캔 100회 후에도 느려지거나 오류가 없는지.
- [ ] **iPad 가로 거치**: 데스크 거치대에 가로로 두고 사용 가능한지.

## 연결 단절과 복구 (오프라인 큐 없음)

새 앱은 오프라인 셸·스캔 큐를 제공하지 않는다. 아래는 실패가 정직하게
드러나는지 보는 항목이며, "끊겨도 저장된다"는 약속이 아니다.

- [ ] **비행기 모드에서 진입**: 연결 없이 새 앱 경로를 열면 오류 안내와
      재시도 경로가 보이는지. 확정된 것처럼 보이는 처리가 없는지.
- [ ] **처리 중 단절**: 스캔·제출 중 연결이 끊기면 실패로 표시되는지.
      서버 확인 전 기록이 확정 체크인으로 보이지 않는지.
- [ ] **복구 후 재시도**: 연결이 돌아오면 같은 조작을 다시 했을 때 멱등
      재시도로 이어지는지(중복 체크인 없이). 대기 항목이 "이어진다"고
      말하지 않는다 — 큐가 없으므로 재조작이 필요하다.

## iOS Safari (iPhone)

- [ ] 체크인 화면이 주소창을 침범하지 않는지.
- [ ] 당겨서 새로고침이 체크인 중 실수로 발동하지 않는지.
- [ ] 홈 화면에 추가 → standalone 실행 시 상단 여백이 정상인지.
- [ ] 다크 모드에서 글자가 읽히는지.
- [ ] 개인정보 보호 브라우징에서도 로그인이 되는지.

## Android Chrome

- [ ] 뒤로 가기 버튼이 앱 내 이동과 충돌하지 않는지.
- [ ] 홈 화면 추가 후 standalone 실행이 정상인지.
- [ ] 저사양 기기에서 체크인 화면이 3초 이내 뜨는지.

## 참가자 화면

- [ ] 티켓 링크를 문자로 받아 열었을 때 QR이 정상 표시되는지.
- [ ] QR을 다른 기기 화면에서 스캔했을 때 인식되는지 (밝기 포함).
- [ ] 현장 등록 폼에서 소프트 키보드가 입력을 가리지 않는지.
- [ ] 짧은 화면에서 참가자 홈의 배너·5개 메뉴가 깨지지 않는지
      (긴 글자·확대에서는 필요한 세로 스크롤이 허용된다).

## 확인 결과 기록

각 항목은 확인한 기기·OS 버전·날짜와 함께 기록한다. 실패 항목은 재현
경로와 함께 이슈로 남긴다. 확인하지 않은 항목을 "통과"로 적지 않는다.
스크린리더 실제 청취·문자 실발송은 이 목록이 아니라 각 정본 문서
(`docs/ARCHITECTURE.md`·`docs/INTEGRATIONS.md`)의 미검증 항목으로 둔다.
