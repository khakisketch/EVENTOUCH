# EVENTOUCH 부스 인증 지도 설계

상태: 대화에서 기능 범위와 이 설계안 검토를 승인했다. 구현 계획 검토는 별도이며, 코드 구현·화면 검증 완료를 뜻하지 않는다.

## 1. 목적과 승인 범위

고객이 요청한 부스 이용·스탬프 인증 현황을 행사 배치도에서 확인한다. 운영자는 기존 부스를 배치도에 연결하고, 참가자는 부스 위치와 본인의 인증 완료 여부를 본다.

- 운영자: 행사 배치도 이미지 등록, 기존 부스 위치 지정, 저장·게시·게시 해제.
- 참가자: 배치도에서 부스 선택, 기존 부스 안내·운영 상태 확인, 인증 완료 표시, 전체 부스 중 인증 완료 개수 확인.
- 인증 기준: 서버가 확정한 기존 `booth.visit` 기록. QR 해독만 성공하거나 요청을 보내기만 한 상태는 완료가 아니다.
- 제외: GPS, 현재 위치, 마지막 인증 위치 강조, 위치 추적, 길 찾기, 위치 확인용 QR, 구역/다각형 그리기, 외부 지도 공급자, 새 보상 규칙.
- 기존 SELF/STAFF 인증 방식, 입장·티켓 검증, 운영 시간·수량·인당 횟수·권한·멱등성은 그대로 유지한다.

결제·환불의 불필요성은 별도 범위 조정 논의다. 이 지도 변경에 결제 체험·공급자 연동을 추가하지 않으며, 기존 결제 코드·데이터 제거를 지도 승인에 포함된 것으로 해석하지 않는다.

## 2. 기존 시스템과의 연결

확인한 현재 소스:

- `server/commands/operations.js`: `booth.save`, SELF/STAFF `booth.visit`, 확정 기록 `workspace.visits`.
- `server/public-events.js`: 공개 부스 목록과 티켓 소유자 본인의 방문 기록만 제공한다.
- `server/state.js`: 행사별 JSONB workspace와 역할별 조회를 제공한다.
- `assets/js/attendee.js`: 기존 `#/event/:slug/stamp` 경로에 스탬프 현황과 인증 동작이 있다.
- PostgreSQL 계획 Task 8: 행사에 귀속된 이미지 파일 업로드·조회 연결은 아직 완료되지 않았다.

지도는 기존 스탬프 화면의 확장이다. 별도의 참가자 계정·인증 서버·방문 기록 저장소를 만들지 않는다. 이미지 파일 연결은 Task 8의 공통 파일 계약을 사용하며, 미완료 상태에서 JSON 파일이나 inline base64를 대체 권위로 추가하지 않는다.

## 3. 운영 흐름

1. 기존 부스 관리에서 행사 부스를 등록한다.
2. 행사별 배치도 이미지 한 장을 업로드한다. 첫 버전은 PNG/JPEG/WebP이며 PDF 지도 편집은 제외한다.
3. 기존 부스를 선택하고 이미지 위에서 위치를 지정한다. 드래그 외에 클릭/터치와 좌표 입력으로도 조정할 수 있어야 한다.
4. 저장 후 게시하면 참가자에게 보인다. 초안 변경은 기존 게시본을 즉시 덮어쓰지 않는다.
5. 이미지 교체 시 새 초안의 위치 지정을 초기화한다. 기존 게시본은 새 게시 전까지 유지한다.
6. 게시 해제해도 부스와 인증 기록은 삭제하지 않는다. 기존 목록형 스탬프 화면을 계속 제공한다.

작성 권한은 기존 부스 관리 범위의 AGENCY/MANAGER에 한정한다. STAFF와 참가자는 지도 설정을 변경할 수 없다. ARCHIVED에서는 변경을 거부한다.

## 4. 참가자 흐름과 집계

- `stamp` 기능이 켜진 행사에서 기존 스탬프 경로를 사용한다. 게시된 지도가 있으면 지도와 부스 목록을 함께 제공한다.
- 지도·부스 안내는 공개 행사 범위에서 볼 수 있지만, 본인의 완료 표시·개수는 유효한 티켓으로만 확인한다. 티켓이 없으면 다른 사람의 상태나 가짜 0개 기록을 보여주지 않는다.
- 인증 완료는 본인 방문 기록의 `boothId`를 기준으로 표시한다. 이름이 같은 부스라도 ID가 다르면 별개다.
- 같은 부스를 여러 번 인증해도 완료한 부스 개수에는 한 번만 포함한다. 기존 인당 허용 횟수·상세 이용 횟수는 유지한다.
- 분모는 현재 행사에 설정된 부스 목록의 고유 ID 수다. 운영 대기·종료 부스와 지도 미배치 부스도 포함하며 목록에서 상태를 구분한다.
- 현재 목록에 없는 부스의 과거 기록은 삭제하지 않지만 현재 진행 개수에는 포함하지 않는다.
- 인증 실패·통신 실패는 완료 표시를 만들지 않는다. 재조회·새로고침 이후에도 서버 기록과 일치해야 한다.
- STAFF 방식에서 다른 기기가 인증한 기록은 다음 서버 재조회/페이지 재진입 시 반영한다. 첫 버전에는 자동 실시간 push/polling을 추가하지 않는다.

## 5. 저장·API 계약

행사 workspace에 `boothMap: { draft, published }`를 추가한다. 값이 없으면 지도 미설정이며 기존 행사 데이터와 호환된다.

각 지도는 행사 귀속 이미지 `fileId` 참조, 검증된 이미지 크기, `points: [{ boothId, x, y }]`, 게시본 버전·게시 시각을 가진다. `x`, `y`는 이미지 좌상단 기준 0~1 비율이다. 지도 좌표는 위치 추적 자료가 아니다.

- 한 부스에 위치 하나만 허용한다. 중복·다른 행사 부스·존재하지 않는 부스·범위 밖/NaN/무한대 좌표를 거부한다.
- 파일은 공통 이미지 allowlist·크기 제한·행사 귀속·접근 정책으로 검증한다. 저장 경로와 비밀값은 공개 응답에 포함하지 않는다.
- 저장·게시·게시 해제는 기존 행사 명령 트랜잭션과 command ID 멱등성을 따른다. 명령은 `booth.map.save`, `booth.map.publish`, `booth.map.unpublish`로 추가한다.
- 게시 시 현재 부스·이미지 유효성을 다시 확인하고 게시본을 스냅샷으로 확정한다. 공개 API에는 게시본만 제공한다.
- 지도 게시 후 현재 부스 목록에서 빠진 ID의 핀은 표시하지 않는다. 지도 좌표 변경으로 과거 인증 기록을 이동·복제·삭제하지 않는다.
- 방문 완료 여부는 기존 본인 방문 기록에서 파생하며 지도에 참가자별 완료 플래그를 별도로 저장하지 않는다.

## 6. 화면 수용 기준

구체적인 화면 구성·스타일·반응형 소스 및 렌더 리뷰는 연결된 디자인 워크스페이스가 맡는다. 기존 EVENTOUCH 브랜드와 승인된 브라우저 우선 참가자 화면을 유지한다.

- 390×844와 1280×900 첫 화면에서 ‘부스 이용 현황’ 목적, 본인 인증 집계 또는 티켓 안내, 지도/목록 접근을 확인할 수 있다.
- 지도 확대·이동 중 핀이 이미지에 붙어 있고, 페이지 스크롤이나 키보드 탐색이 갇히지 않는다. 320px에서도 가로 페이지 넘침이 없다.
- 부스 선택 후 부스명·운영 상태·본인 인증 여부를 확인할 수 있다. 색상만으로 완료 여부를 구분하지 않는다.
- 기본 부스 목록은 지도 없이도 사용할 수 있다. 미게시·이미지 로딩/오류·부스 0개·미배치 부스·무티켓 상태에서 인증 흐름을 잃지 않는다.
- 승인된 실제 파일 예시를 대상으로 지도 확대 시 부스 위치를 식별할 수 있는지 검증한다. 이미지 실패 시 임의 대체 지도나 성공 상태를 만들지 않는다.
- 기존 신청·티켓·입장·스태프 인증 흐름과 SELF/STAFF 동작이 깨지면 실패다.

## 7. 구현 순서와 검증 게이트

1. 이 설계안 검토 후 별도 구현 계획을 확정한다. 현재 미완료 PostgreSQL Tasks 7–8 및 참가자 화면 리뷰와의 순서를 계획에 명시한다.
2. 공통 행사 파일 저장·조회 계약을 완성하고, 서버 지도 검증/명령/공개 projection을 TDD로 추가한다.
3. 실제 소스·상태·자산 입력을 확인한 뒤 디자인 워크스페이스에서 운영자 배치와 참가자 지도 UI를 구현한다.
4. 실제 제품의 대상 화면·빈/로딩/오류·키보드 상태를 캡처하여 생성과 다른 리뷰 스킬로 결함 목록·수정 근거를 검증한다.
5. 독립 Test Runner가 통합된 소스에서 권한/게시 분리/다른 행사 파일·부스 거부/본인 기록 privacy/중복 인증 집계/새로고침 지속성 및 기존 회귀 검사를 수행한다.

운영 DB 접속·배포·외부 게시·새 지도 서비스·의존성 설치는 이 설계 승인에 포함하지 않는다. 제품 승인과 기술 검증은 구분한다.
