# EVENTOUCH 개선 목록

2026-11-02 사용자가 승인한 개선 순서와 완료 기준이다. 고객 기획안은 요구의 근거이며
이 문서의 구현 선택이 고객의 검수·계약 합의를 뜻하지는 않는다. 현재 구현과 검증 수치는
[STATUS.md](STATUS.md), 고객 요구 대조는 [CONTRACT-SCOPE.md](CONTRACT-SCOPE.md)가 정본이다.
상태는 `대기`, `진행`, `검증 완료`, `외부 확인 대기`로 관리한다. `검증 완료`는 구현 범위의 로컬 합성 검증을 뜻하며 고객 승인이나 실연동·실기기 검증을 대체하지 않는다. 병행 작업의 기존 내용을 보존한다.

## 범위와 순서

## 고객 확인이 필요한 차이

- 시간표 이미지는 구조화된 일정의 모바일 가독성·변경 편의와 중복 관리 방지 효과를 시연해 대체 수용을 제안한다. 원본 이미지 표시가 필수로 확인되면 별도 범위로 정한다.
- 고객사 포털·로그인, 결제·기프티콘, 새 조직 설정과 오프라인 처리는 기존 제외 결정을 유지한다.
- 로그인 링크 엑셀은 티켓 노출 위험으로 포함하지 않는다. 관리자 IP/기기 로그·로그인 기록 보존기간, 행사 영구 삭제, 조직별 실제 발송 계정과 과금은 고객·운영 정책을 확정하기 전 임의로 정하지 않는다.
- Q&A 반려는 참여 화면에서 확인하며 새 문자·푸시를 발송하지 않는다. 법적 문구는 승인된 원문이 확보되면 연결한다.
- 데스크의 이름·소속 대조는 현장 수동 확인이며 강한 본인 인증을 뜻하지 않는다. 실제 행사에서 허용할 신원 확인 방법과 동명이인·소속 미입력자의 처리 책임을 고객과 확인한다.

## 기술·검증 계약

- 모든 행사 쓰기는 기존 이벤트 커맨드의 멱등·행 잠금·영수증·권한·감사 경로를 따른다. 조직 범위 쓰기와 메시지 커밋 후 발송 규율도 유지한다.
- 새 읽기 인터페이스는 범위와 현재 접근 권한을 확인하고 원문·연락처·토큰 등 불필요한 영수증 응답을 노출하지 않는다. 미확정 상태에서 재발송하지 않는다.
- 기존 데이터에는 현재 동작을 기본값으로 적용한다. 참가자 홈 `homeStyle`의 필드와 검증은 유지하고 메뉴 설정은 별도 초안/게시 속성으로 다룬다.
- P1·P2 변경은 새 빌드의 실제 브라우저→API→데이터 결과와 오류 복구를 확인한다. 동작 계약 검사를 약화하지 않고 표현 검사 변경은 이유를 현황에 기록한다.
- 실발송·기기·스크린리더 실청취·실제 프린터·고객 승인·운영 부하는 자동/합성 검사 결과로 대신하지 않는다.
