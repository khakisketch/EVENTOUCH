# EVENTOUCH 디자인 시스템

Updated: 2026-10-23 · 토큰 정본: `apps/web/app/tokens.css`

새 화면을 만들 때 이 문서대로 만든다. 값을 새로 발명하지 않는다. 여기에 없는 것이
필요하면 토큰을 먼저 추가하고 이 문서를 갱신한다.

검증은 실행 중 Next 빌드 대상 감사(`npm run web:audit`·`npm run a11y`·`npm run mobile`)가
결과를 검사한다. 구 앱(바닐라)의 `E.*` 헬퍼·`od-*` 프리미티브·구 체크리스트는 은퇴와 함께
효력을 잃었다. 아래는 새 앱(`apps/web`, CSS 모듈 + 공용 콘솔 부품) 기준이다.
참가자 홈의 고객 레퍼런스는 한울 기획안 **3·4쪽 왼쪽 휴대폰 화면 이미지**다.
행사 키비주얼 아래 연한 하늘색 배경에 흰색 아이콘 메뉴를 2열로 배치한다
(원본은 ①② / ③④ / ⑤). 이 구조를 바탕으로 현재 고객사 확정 구성은 **6개 메뉴·2열 3행**이다.
메뉴를 누르면 상세 화면으로 들어가고 메뉴로 돌아온다.
슬라이드의 네이비 `상시 확인 가능`·`특정 시간에 운영` 막대와 노란 번호 원은
설명용 주석이지 휴대폰 UI가 아니다. 이를 화면에 옮기지 않는다.
운영 콘솔의 EVENTOUCH 브랜드와 참가자 행사 테마는 구분하고, 행사별 게시 키비주얼을 우선한다.
기본 배너는 PDF에서 분리한 원본 꽃·캐릭터 아트(`apps/web/public/attendee-home-banner.png`)를
사용한다. 샘플 행사의 문구는 제거하고 실제 행사명을 겹친다. 유사하게 새로 그린 SVG로
바꾸지 않는다. 메뉴 아래에 선택 상세를 계속 붙이지 않고 별도 보기와 실제 뒤로가기를 유지한다.
참가자 홈은 기본 글자 크기에서 **배너와 6개 메뉴를 스크롤 없이 한 화면에** 담는다.
주소창을 제외한 짧은 화면에서는 정사각형 타일을 고집하지 않고 배너·타일 높이와 간격을
가용 높이에 맞춘다. 2열 배치·원본 아트·메뉴 이름·44px 이상 터치 영역은 유지한다.
`overflow:hidden`이나 전체 화면 축소로 내용을 숨기지 않는다. 큰 글자·확대에서는
필요한 스크롤을 허용하고 긴 공지·투표 목록 같은 상세에는 이 한 화면 제약을 적용하지 않는다.

### 행사별 참가자 홈 꾸미기

공통 PDF 아트·하늘색은 **미설정 행사의 기본값**이지 모든 고객사에 고정할 디자인이 아니다.
행사 운영자는 기존 행사 콘솔 안에서 배경색·배너 이미지·대표/보조 문구·배치·크기·정렬·
밝은/어두운 글자와 이미지 덮개·사진 초점을 설정한다. 임의 HTML/CSS/외부 폰트나 추적용
이미지 URL을 받는 자유 캔버스는 제공하지 않는다. 글자가 포함된 배너에는 이미지 전용
배치를 제공하되 접근성용 행사 제목은 유지한다.

편집 → 휴대폰 미리보기 → 초안 저장 → 명시적 게시를 구분한다. 미리보기는 참가자 홈과
같은 표시 컴포넌트를 사용하고 참가자 행동을 실행하지 않는다. 저장되지 않은 변경·저장된
초안·참가자에게 게시된 화면을 혼동시키지 않는다. 초안은 공개 응답·이미지 경로로 노출하지
않고, 같은 행사의 모든 참가자에게 같은 게시 디자인을 제공한다. 다른 행사의 디자인은
바꾸지 않는다. 큰 글자·긴 제목에서는 읽을 내용을 숨기는 대신 필요한 세로 스크롤을 허용한다.

새 앱 콘솔은 확정 내비게이션 껍데기를 살리는 절충 방향을 따른다(다크 사이드바·랜드마크·
행사/고객사 메뉴). 토큰 값 자체는 바꾸지 않는다.

시각 POV: 현장 아티팩트. 범용 어드민 관용구로는 행사 제품의 특정성이 드러나지
않으므로, 설득이 필요하면 일러스트·목업 대신 실제 화면·티켓·현장 산출물을 증거로
쓴다(`apps/web/public/evidence/`, 랜딩 `실제 화면` 절). 토큰·레이아웃은 그대로 두고
증거의 선택으로 말한다. 참가자 티켓은 단일 절취선·입장 상태·여유 있는 QR로, 행사 홈은
정렬된 D-day·날짜와 상태 점이 붙은 단계 배지로 현장 흐름을 드러낸다.

## 1. 토큰

전부 `apps/web/app/tokens.css`의 `:root`에 있다. 컴포넌트 CSS는 이 변수만 쓰고 리터럴 색을 쓰지 않는다.
값은 구 토큰 체계를 그대로 계승한다. 앱 전용 추가 토큰(레이아웃 상한·참가자 강조·전화기 스테이지 등)은
해당 화면에서만 쓰고 전역 의미를 늘리지 않는다.

## 2. 레이아웃과 스타일 구조

새 앱은 CSS 모듈(화면별 `*.module.css`) + 전역(`globals.css`) + 콘솔 공용 부품
(`console-ui/`)으로 구현한다. 구조·시각의 경계는 파일로 나뉘며, 구 앱의 전역
`od-*` 프리미티브는 은퇴했다. 새 화면은 기존 모듈·부품을 재사용하고, 새 값을
만들기 전에 토큰과 기존 모듈을 먼저 본다.

핵심 규칙(구 앱에서 반복된 실수의 교훈): **라벨·값을 세로로 쌓는 정보 단위는
각 조각을 자기 줄에 둔다.** 데이터 텍스트 자르기는 꼭 필요한 곳에만 쓰고,
문장은 문구를 줄인다.

## 3. 컴포넌트

콘솔 화면은 공용 부품(`ConsolePageHeader`·`ConsoleSection`·`ConsoleStatePanel`,
`apps/web/app/console/console-ui/`)을 조합한다. 머리·섹션 제목·초기 상태 표현을
한 곳에서 유지하므로, 한 화면마다 다른 제목 크기·뒤로가기 위치·오류 복구 모양이
생기지 않는다. 부품별 prop 계약과 운영 현황·배지·사진 규칙은 아래 10절에 둔다.

구 앱의 문자열 헬퍼(`E.head`·`E.panel`·`E.table`·`E.field` 등)와 호출 수 기록은
은퇴와 함께 효력을 잃었다. 새 화면은 그 헬퍼를 쓰지 않는다.

유지되는 표현 규칙:

- **한 화면에 주행동(primary)은 하나.** 헤더·섹션 머리 액션 슬롯에는 보조 스타일만 둔다.
- 피드백은 네 가지를 구분한다: 화면에 남는 설명 / 잠깐 사라지는 결과 알림 /
  입력을 받는 모달 / 데이터가 없을 때의 빈 상태 + 다음 행동.
- 상태 라벨은 한국어로 쓴다. 원시 키(`SENDING`, `PARTIAL`)를 화면에 노출하지 않는다.
- 전화번호·수량 입력에는 `inputmode`와 `autocomplete`를 지정한다. 금액·수량은 `inputmode="numeric"`.
- 사라지는 결과 알림을 남는 설명 대신 쓰지 않는다. 반대로 저장 결과를 남는 설명으로 남기지 않는다.

### 콘솔 내비게이션

| 요소 | 규칙 |
|---|---|
| 메뉴 행 | 데스크톱·모바일 모두 최소 **44px**. 밀도를 맞추려고 44px 아래로 줄이지 않는다 |
| 그룹 소제목 | 클릭 불가. 그룹을 접어 숨기지 않고 소제목으로 나눈다 |
| 현재 위치 | 배경 + 좌측 강조선 **두 신호**. 색만으로 표시하지 않는다 |
| 상위 경로 | 현재 행사 안에 있을 때 `행사` 항목도 함께 표시 |
| 행사 하위 트리 | 들여쓰기 + 좌측 가이드선으로 부모 관계를 보인다 |
| 운영자 메뉴 | 데스크톱은 사이드바 하단, 모바일은 상단 계정 버튼의 팝오버. Escape로 닫으면 실행 버튼으로 복귀한다 |

- 메뉴가 길어지면 **메뉴 영역만** 스크롤한다. 하단 운영자 블록이 화면 밖으로 밀리면 안 된다.
- 기능이 꺼진 목적지와 권한 없는 목적지는 **렌더하지 않는다**(빈 자리표시자를 만들지 않는다).
  이것은 표시 게이트일 뿐이며 권한 판정은 항상 서버가 한다.
- 모바일에서는 행사·고객사의 하단 고정 바를 두지 않는다. 상단 `메뉴`를 열면 기존 권한으로 허용된
  `행사 목록`·`고객사`만 작은 비모달 펼침 메뉴에 표시한다. 현재 행사 업무 가로 탐색과 계정 메뉴는 별도다.
  데스크톱은 기존 사이드바를 유지한다.
- 행사 내비게이션은 운영 현황 / 모집·안내(참가자·메시지·콘텐츠·참가자 페이지) / 현장 진행
  (현장 운영·참여 프로그램·추첨·투표·경품·현장 사진) / 결과 보고서 / 행사 설정 순서다.
  그룹 라벨은 클릭하거나 접을 수 없으며 목적지·권한·기능 게이트는 그대로다. 모바일 가로 목록은
  현재 위치를 따로 표시하고 행사별 가로 스크롤 위치를 복원한다. 전역 `메뉴`와 합치지 않는다.
- 상단 메뉴는 Enter/Space로 열고 첫 목적지에 포커스를 둔다. Escape는 닫고 실행 버튼으로 복귀하며,
  바깥 클릭·Tab 이탈은 새 포커스를 빼앗지 않고 닫는다. 계정 메뉴와 동시에 열지 않는다.
  경로 이동은 기존 미저장 경고를 거치고, 이동 취소 시 메뉴·입력을 유지한다. 현재 목적지 선택은 메뉴만 닫는다.

### 대시보드 블록 (운영 현황)

| 요소 | 규칙 |
|---|---|
| 지표 타일 | 숫자를 먼저 읽히게. 타일당 라벨 + 값 + 단위 |
| 할 일 행 | 주 행동 하나 + 대기 건수 행. 대기가 0이면 그 사실을 쓴다 |
| 진행/추이 | 기록이 적으면 비어 보인다. 기준을 한 줄로 밝힌다(예: "정정되지 않은 입장 기록 기준") |
| 그룹 간격 | 그룹 사이 24px, 그룹 안 4~12px. **모든 블록을 같은 간격으로 쌓지 않는다** |

## 4. 상태 표현 규칙

빈 상태·오류·로딩을 **각각 다르게** 표현한다.

- **빈 상태**: 왜 비었는지 + 다음 행동을 준다. 권한 때문에 걸러진 경우와
  진짜 0건을 구분해서 쓴다.
- **오류**: 화면 내 오류 안내 또는 폼이면 오류 요약(`role="alert"`). 실패에는
  보조 `다시 불러오기` 버튼을 제공한다(`ConsoleStatePanel`).
- **로딩**: `role="status"` + "...를 불러오고 있습니다." 문구.
- **연결 단절**: 오프라인 셸·큐는 없다. 무엇이 안 되는지 알리고 재시도 경로를 준다.
  서버 확인 전 기록을 확정으로 표시하지 않는다.

상태 라벨은 한국어로 쓴다. 원시 키(`SENDING`, `PARTIAL`)를 화면에 노출하지 않는다.

## 5. 반응형

새 규칙은 768/1024 구간에 붙이고, 기기 폭별 미세 구간을 늘리지 않는다.

| 구간 | 규칙 |
|---|---|
| `≤768px` | 페이지 머리 세로 배치, 폼 1열, 표 → 카드 전환, 탭 가로 스크롤 |
| `≤1024px` | 2열 배치를 1열로 |

**터치 타깃 최소 44px.** `npm run mobile`이 위반을 잡는다(WCAG 인라인 예외·
라벨 면적 인정 규칙은 감사 스크립트 주석을 따른다).

## 6. 접근성

- 포커스: `outline: 3px solid var(--focus)`, `outline-offset: 3px`. 모든 상호작용 요소.
- 모달: `role="dialog"`, `aria-modal`, `aria-labelledby`, 열 때 첫 요소 포커스,
  Escape 닫기, 닫을 때 이전 포커스 복귀.
- 토스트: `role="status"` + `aria-live="polite"`. 오류 요약은 `role="alert"`.
- 라벨 없는 입력을 만들지 않는다. 아이콘만 있는 버튼은 `aria-label` 필수.
- 색만으로 의미를 전달하지 않는다 — 배지에 글자가 함께 있다.
- `prefers-reduced-motion`이면 전환·애니메이션을 끈다.
- 건너뛰기 링크(`.skip-link`, 루트 레이아웃 첫 요소)가 본문으로 이동한다.

## 7. 인쇄

`@media print`에서 셸·툴바·탭·토스트·모달을 숨기고 본문만 남긴다. 보고서는 브라우저
인쇄 → PDF 저장 경로를 쓴다.

## 8. 은퇴한 패턴 (따르지 않는다)

구 앱과 함께 효력을 잃은 것들이다. 새 화면에 옮기지 않는다.

- 문자열 헬퍼·호출 수 기록·폼 등록 방식·뷰/액션 중복 정의와 로드 순서 계약.
- `od-*` 레이아웃 프리미티브와 그 사용률 측정값.
- 오프라인 셸·스캔 큐·외부 QR 알고리즘 벤더 기록.

## 9. 새 화면 체크리스트

1. 콘솔은 `ConsolePage`와 중앙 메뉴 레지스트리로 머리·폭·시작선을 맞춘다. 본문은 `ConsoleSection`·`ConsoleStatePanel` 등 공용 부품으로 구성한다.
2. 상태는 빈 상태 / 오류+재시도 / 로딩 중 의미에 맞는 것을 쓴다.
3. `primary`는 현재 작업 단위의 핵심 행동에만 쓴다. 독립 저장 구역의 저장·게시·발송은 합치지 않는다. 헤더·섹션 머리 슬롯은 보조만.
4. 하드코딩 색·간격을 쓰지 않는다. 토큰만.
5. 320/390/768/1024/1280에서 확인한다.
6. `npm test`, `npm run a11y`, `npm run mobile`, `npm run web:audit`을 돌린다. 콘솔 구성·이동 변경은 `npm run web:console:audit`도 확인한다.

## 10. 콘솔 페이지 구조 중앙화

적용 범위는 Next.js `apps/web/app/console/**`다. 목표는 부품 수가 아니라 **메뉴를 바꿔도 현재 위치,
조회 조건, 주요 행동과 저장 위치를 다시 찾지 않는 것**이다. 사용자가 지적한 화면별 차이는 바깥
정렬만의 문제가 아니므로 제목·행사 문맥·도구막대·섹션·입력·작업 버튼·피드백·대화상자를 공통 소유자로 옮긴다.
지도·달력·갤러리·추첨 결과·휴대폰 미리보기 등 업무 내용의 구조까지 같게 만들지는 않는다.

### `console-navigation.ts`와 `ConsolePage`

- 레지스트리는 기존 목적지의 이름·경로·범위만 관리한다. API·권한 판정이나 새 라우트를 만들지 않는다.
  셸과 페이지가 같은 이름을 사용하고, 명단 가져오기는 별도 페이지 제목이면서 참가자 메뉴를 활성화한다.
  참가자 대기 필터·메시지 확인 필터와 해시는 각 업무가 계속 소유한다.
- `ConsolePage`가 유일한 메뉴 페이지 프레임이다. 전체 폭은 `--web-content-max`, 자동 중앙 정렬,
  공통 헤더·본문 간격을 사용한다. 개별 화면에 760/880/1440px 외곽 폭을 다시 두지 않는다.
- 행사 하위는 작은 `행사 / 행사명` 문맥 링크 → `h1=메뉴명` → 받은 일정·고객사·장소 메타 → 필요한 상태 배지다.
  운영 현황도 같은 규칙이다. 최상위 행사·고객사·팀에는 행사 문맥을 넣지 않는다. 별도 `← 운영 현황` 행은 중복하지 않는다.
  로딩·실패·권한 제한도 같은 메뉴 제목과 프레임을 유지한다. 없는 행사를 빈 참가자 목록처럼 보이지 않게 한다.
- 기본 슬롯은 `headerActions`(보조), `toolbar`, `sectionNav`, `feedback`, 본문이다. 버전·단계는 `badges`로 전달한다.
  페이지 컴포넌트는 데이터·권한·쓰기·입력 상태를 계속 소유한다. 공통 프레임에 도메인 상태나 자동 저장을 넣지 않는다.

### 도구막대·본문·저장 규칙

| 업무 유형 | 공통 배치 | 보존할 차이 |
|---|---|---|
| 목록 | `ConsoleToolbar`: 조회 조건 왼쪽, 등록/가져오기 오른쪽, 선택 작업은 선택 시 별도 행 | 행사 달력·참가자 조밀한 행·파일/이미지 내용 |
| 관리 | 공통 섹션 제목·관련 보조 액션·본문, 장문 화면은 `ConsoleSectionNav` | 지도·추첨 결과·운영 기록·갤러리 |
| 작성 | `ConsoleSection width="form"` 안의 읽기 폭, 편집 단위 아래 `ConsoleFormActions` | 저장·게시·발송의 명령과 확인 절차 |
| 현황 | 전체 공통 폭, 지표·표·읽을 글은 내부에서 필요한 폭 적용 | 실시간 분석과 동결 보고서의 명확한 구별 |

- 섹션은 기본 `surface="plain"`, 필요할 때만 `panel`이다. 모든 목록·하위 구역을 겹친 카드로 감싸지 않는다.
  `width="form"`은 섹션 머리가 아니라 내부 입력 영역만 `--web-reading-max`로 제한하여 시작선을 유지한다.
- `ConsoleFormActions`는 배치만 제공한다. 폼 연결·버튼 `type`·요청 식별자·저장 의미는 각 편집 단위에 남긴다.
- `ConsoleFeedback`은 오류/성공/주의/정보를 공용 톤과 의미로 구별한다. 평상시 미입장은 경보 건수에 합산하지 않는다.
  미입장 드릴다운은 `status=APPROVED&attendance=NOT_ENTERED`와 눈에 보이는 출입 필터를 함께 사용한다.
- 참가자 페이지 편집기는 공통 프레임 **안에서만** 편집/휴대폰 미리보기 분할을 사용한다. 모바일은 편집 → 저장/게시 →
  미리보기 순서이며, 섹션 바로가기로 긴 화면을 이동한다. 미리보기는 실제 참가자 홈 컴포넌트다.
- 도구막대는 첫 자식을 검색으로 추측하지 않는다. 한 행을 차지할 검색/필터 묶음은 `data-toolbar-span="full"`,
  의도적으로 나란히 두는 짧은 보조 행동은 `data-toolbar-inline`로 명시한다. 모바일의 일반 실행 버튼은
  전체 폭으로 쌓고, 검색 옆에 긴 체크박스 문구를 끼워 넣지 않는다.
- 행사 목록의 진행 단계는 보조 조회 조건이므로 내용 카드처럼 흰 면·둥근 테두리로 강조하지 않는다.
  고유 폭의 평평한 기본 드롭다운으로 표현하되 기본 화살표·선택 창·포커스 링·44px 높이는 유지한다.
  지원 브라우저에서는 선택한 문구에 폭을 맞추며, 승인 대기 조건과의 간격은 `--s3`로 일정하게 유지한다.
  내용 폭으로 바꾼 뒤에도 모바일의 옛 비율 분할을 남겨 화면 폭에 따라 빈 띠가 커지게 하지 않는다.
  이 규칙을 데이터 입력 폼의 모든 select에 일괄 적용하지 않는다.
- 행사 목록·달력의 행사 카드는 **행사를 식별하고 들어가기 위한 요약**이다. 행사명·일시·고객사/장소·
  진행 단계는 유지하고 등록 인원·현재 입장·정원과 같은 상세 통계는 행사 안의 운영 현황에서 읽는다.
  승인 대기가 실제로 있을 때만 작은 `승인 대기 N명 처리` 링크를 별도 보조 행동 행에 둔다.
  대기가 없으면 `0명` 지표나 빈 알림 영역을 만들지 않는다. 행사 진입 링크와 처리 링크는 중첩하지 않고
  각 행동의 포커스·44px 높이를 유지한다. 승인 정책·참가자 상태·기존 조회 조건은 바꾸지 않는다.
- 행사 카드는 **A2 소프트 헤더**다. 제목과 묶은 날짜·시간 한 줄은 연한 헤더 면에, 고객사/장소와
  단계·D-day·장식용 열기 화살표는 종이 본문에 둔다. 카드 전체가 행사 홈으로 들어가는 하나의
  링크이며, 승인 대기 링크만 그 밖에 따로 둔다. 카드에 복제 동작을 두지 않고 항상 비는
  바닥글도 만들지 않는다. 대기가 없으면 바닥글 자체가 없다.
- 카드 헤더 면은 **게시된 참가자 홈 배경만** 따른다. 이미 읽은 bootstrap의
  `workspaces[*].pageExperience.published.homeStyle.backgroundColor`를 쓰고, `publishedAt`
  표시가 없는 초안·미게시·무효 색은 기존 `--soft`로 둔다. 게시색은 흰색에 15%를 섞은 옅은
  틴트로만 쓰고(`event-card-theme.ts`), 게시 헤더의 날짜 글자는 본문 잉크로 고정한다.
  운영자 색마다 관계없는 주황 글자를 얹지 않으며, 4.5:1은 유지한다. 기본 `--soft` 면에서만
  기존 브랜드 글자색을 쓴다. 단계 배지의 의미색은 행사 테마로 물들이지 않는다.
  카드별 추가 조회·새 서버 필드·낙관적 미게시 미리보기가 없다.

### 정보 필요성 판단 기준

같은 값이라도 화면의 목적에 따라 상시·조건부·상세로 나눈다. 값이 존재한다는 이유로 모든 화면에 복제하지 않는다.
검토 결과는 업무 단위(참가자·안내·현장·참여·결과·공개)로 나누어 진단→개선→실제 조작 확인 순서로 반영한다.

- 선택 인원·수량 계수는 **현재 화면에 보이는 선택**과 **전체 선택 합계**를 구분해 쓴다. 숨김·필터 밖 선택은
  숨기지 않고 계수에 포함해 알린다. 상한(예: 발송 200명)은 초과 시점의 안내 행과 함께 유지한다.
- 가져오기·일괄 등록처럼 서버가 상태를 정하는 경로는 결과 상태(예: 참가 확정, 동의 기록 없음)를 실행 버튼
  가까이에 명시한다. 화면이 서버 규칙을 요약하지 않으면 운영자는 검토 절차를 기대한다.
- 대상 조건이 있는 실행(추첨 등)은 서버 풀 조건을 문구로 그대로 밝힌다(예: 입장·체크인 완료 + 승인 상태).
  조건을 알 수 없으면 현장에서 제외 이유를 설명할 수 없다.
- 기능 토글이 다른 입력의 의미를 바꾸면(예: 결제 기능과 참가비) 현재 조합의 실제 결과를 그 입력 옆에 쓴다.
  연동 전 기능이 참가자 흐름을 막는 경우에도 숨기지 않고 화면에 적는다.
- 게시/초안이 나뉜 자산(부스 지도 등)은 저장과 게시를 다른 상태로 보여주고, 초안만 있고 게시본이 없거나
  게시본과 다르면 참가자에게 무엇이 보이는지 문구로 알린다. 성공 메시지가 게시를 대신하지 않는다.
- 잔여 수량은 정원이 있는 경우 `인증 N회 · 잔여 M / 정원`처럼 **사용량·잔여·정원을 함께** 쓴다.
  "제한 없음"은 정원 미설정일 때만 쓴다.
- 생성한 뒤 되돌리기 어려운 자원(데스크 등)은 서버가 제공하는 편집 경로를 화면에도 제공한다. 방향·기준이
  바뀌면 서버가 요구하는 확인을 같은 문구로 묻고, 저장하지 않은 상태·열림 상태를 임의로 바꾸지 않는다.
- 참가자에게 보이는 분류·배지 문구는 한국어로 쓴다. 내부 키·영문 라벨은 화면에 내보내지 않는다.
- 상세 통계·판정 규칙(채점 기준, 집계 정의)은 상세 화면에 두고, 목록 화면은 식별·상태·다음 행동에 집중한다.
- 부스 인증은 두 방식 모두 참가자 홈에서 이름이 같은 목적지 하나를 쓴다. 셀프 방식은 부스 QR의
  `ET:BOOTH:` 코드를 붙여넣어 제출하고(앱 내 카메라 스캔을 전제로 하지 않는다), 스태프 확인 방식은 배정
  스태프가 처리한다. 입장(체크인)·부스 상태·인원·횟수 판정은 서버 문구를 그대로 보여준다.
- 이 제품은 결제를 처리하지 않는다. 결제 기능 토글을 화면에 두지 않고, 참가비는 청구·수납에 쓰이지
  않는다는 사실을 입력 옆에 밝힌다. 참가자 티켓·체크인은 결제 상태로 막지 않는다.
- 서로 다른 기능에 같은 이름을 쓰지 않는다. 순위(랭크) 투표와 참여 프로그램의 투표 모듈은
  `순위 투표`/`투표`로 구분해 표기한다(참가자 홈 타일 포함).
- 모바일 참가자 목록은 검색을 먼저 보이고 상태·그룹·출입은 `필터`에서 펼친다. 적용 개수·요약은 접어도 보이며,
  필터가 담긴 직접 링크는 펼쳐 시작한다. `검색·필터 초기화`는 명단 선택을 지우지 않는다.
- 참가자 명단은 데스크톱 압축 행·모바일 카드와 25명 페이지를 사용한다. 현재 페이지 선택·전체 선택을
  구분하고, 승인·그룹 지정의 기존 필터 범위와 메시지 인계의 전체 선택 범위를 실행부에서 밝힌다.
  다른 페이지·필터 밖 선택은 유지하며, 목록 하단에서 검색으로 초점을 돌릴 수 있다.
- 메시지는 작성과 수신자 선택을 데스크톱 두 열·모바일 한 열로 배치한다. 검토 바는 선택 수·채널·
  모의/실제/수동 예약을 실행 버튼 가까이 보여 주며, 템플릿 관리·발송 기록은 작성 아래에서 펼친다.
  수신자를 고르기 전에도 작성할 수 있고 검토는 기존 발송 확인을 열 뿐 자동 전송하지 않는다.
- 참가자 페이지 편집기의 초안 저장·게시와 변경 상태는 편집 영역의 고정 저장 바에서 확인한다.
  기본 배경·배너·문구는 노출하고 초점·배치·글자 톤·덮개는 상세 설정으로 펼친다.
  병렬 미리보기의 소스·크기 전환이 편집 위치 안내를 바꾸지 않는다.
- 모바일 섹션 바로가기는 화면 안에 줄바꿈하여 모든 목적지를 보여준다. 행사 전환용 셸 가로 메뉴와 구분한다.
  앵커·키보드 스크롤에는 상단 고정 메뉴의 여유를 두고, 하단은 일반 여백과 safe-area만 유지한다.
  사라진 하단 바를 위한 빈 공간을 남기지 않고 마지막 행동까지 스크롤할 수 있게 한다.

### 대화상자·입력 생명주기

- `ConsoleDialog`가 초기 포커스·Tab 순환·Escape·배경 클릭·스크롤 잠금·포커스 복귀를 맡는다.
  페이지별 문서 키보드 리스너와 스크롤 잠금을 함께 실행하지 않는다. 빈 포커스 목록과 사라진 실행 버튼도 처리한다.
- 업무는 `busy` 및 동기 `canClose`로 쓰기 도중 닫힘을 막는다. 변경된 내용의 폐기 확인은 Escape/배경/취소에 같은 규칙을 쓴다.
  응답 불명 상태를 “취소됨”이라 하지 않으며 이미 저장됐을 가능성과 같은 요청 재확인을 안내한다.
- `useConsoleDraftGuard`는 업무가 전달한 미저장 차이·미확인 요청을 등록한다. 같은 탭의 메뉴/행사 이동·로그아웃 및
  브라우저 새로고침/닫기에 경고한다. 조회 필터·섹션 앵커·다운로드·새 탭은 막지 않는다. 자동 저장이나 브라우저 저장소는 추가하지 않는다.
  브라우저 뒤로/앞으로의 입력 복원, 탭 종료 후 복구, 오프라인 작업은 보장하지 않는다.
- 요청 식별자는 행사·명령·변하지 않는 페이로드 지문에 묶는다. 응답 유실 뒤 같은 입력은 같은 영수증을 재확인하고,
  달라진 입력은 새 요청이다. 앞선 응답으로 나중 입력을 덮지 않는다. 참가자 페이지는 낙관적 버전 충돌 복구도 유지한다.
- 읽기·관리 권한과 단계별 가능 행동을 나눈다. 현재 서버 규칙대로 보관 행사는 도메인 쓰기를 막고, 참가자 변경은 종료에서도 막는다.
  읽기·내보내기·미리보기는 유지한다. 레지스트리나 미집행 세부 권한 메타로 새 정책을 만들지 않는다.

### `ConsolePageHeader`

`ConsolePage` 내부의 표현 부품이다. 순서는 작은 행사 문맥 → 32px 메뉴 `h1` → 메타 한 줄 → 선택적 배지 → 우측 보조 액션이다.
메타는 고객사 · 날짜 · 시간 · 장소 순서이며 빈 값은 생략한다. 768px 이하에서는 단일 보조 액션을 제목 옆에,
여러 보조 액션은 메타·배지 아래에 둔다. 행사 문맥과 메타 폭을 액션 때문에 좁히지 않는다.
호환용 `back` prop은 남아 있지만 메뉴 페이지가 직접 헤더를 만들거나 중복 복귀 행을 넣지 않는다.
헤더 액션은 이동·보조 작업뿐이며 `button-secondary`를 사용한다.

| prop | 용도 |
|---|---|
| `title: string` | `h1` 제목 |
| `back?: { href, label }` | 컴팩트 뒤로가기 링크 |
| `meta?: ReactNode` | 고객사·일정·장소 정보. 행사 메타는 `formatConsoleEventMeta`로 정규화 |
| `badges?: ReactNode` | 운영 현황의 단계·접수·일정 배지 |
| `actions?: ReactNode` | 우측 보조 액션. 주황 primary 금지 |
| `className?: string` | 기존 화면 구조의 국소적인 배치 보존 |

뒤로가기 링크는 DOM·키보드 순서상 제목과 메타, 헤더 액션보다 먼저 온다. 공통 CSS는 제목 32px,
메타 글자·간격, 헤더 하단선을 제공한다. 좁은 폭에서도 제목과 보조 행동의 관계를 유지하며 44px 버튼 크기는
전역 규칙에 맡긴다. 제목이 길면 읽을 수 있게 줄바꿈하며 글자 크기를 줄여 맞추지 않는다.

### `ConsoleSection`

페이지의 각 의미 단위는 이 부품으로 묶는다. 제목은 `h2`, 설명은 선택적 보조 문장, 액션은 선택적
보조 액션이다. 컴포넌트가 `headingId`를 `h2 id`와 `section aria-labelledby`에 함께 연결한다.
운영 현황에서 가져온 기준은 제목 `--h3`(20px), 줄 높이 1.35, 설명 `--small`(14px), 제목-설명
간격 `--s1`, 섹션 간 기본 간격 `--s3`다. `density="compact"`는 짧고 응집된 목록에만 제한하고,
주의 항목을 새 카드 스트립으로 늘리지 않는다. 카드 배경·경계는 해당 작업 영역이 이미 가진 표현을
`className`으로 유지할 수 있다.
제목과 보조 액션은 같은 행, 설명은 그 아래 전체 폭을 사용한다. 긴 설명 때문에 액션만 별도 행으로 밀리지 않는다.

| prop | 용도 |
|---|---|
| `headingId: string` · `title: string` | 접근성 이름과 섹션 제목 |
| `description?: ReactNode` | 제목 아래 보조 설명 |
| `action?: ReactNode` | 보조 액션만. 주황 primary 금지 |
| `children: ReactNode` | 섹션 본문 |
| `className?: string` | 기존 카드/그리드 배치 보존 |
| `density?: "default" \| "compact"` | 기본 간격 또는 확인 필요처럼 압축된 밀도 |
| `divider?: boolean` | 기존 패널 헤더의 아래 구분선 유지 |

### `ConsoleStatePanel`

초기 로딩은 `role="status"`와 “...를 불러오고 있습니다.” 문구를 쓴다. 실패는 `role="alert"`와
보조 `다시 불러오기` 버튼을 제공한다. 버튼은 `eventouch:shell-reload`를 dispatch한 뒤 페이지의
기존 재조회 함수를 호출한다. 선택적 `actions`는 가져오기 같은 단계 흐름의 복귀 경로를 유지할 때만
사용한다. 각 페이지는 데이터·권한 판단과 재조회 동작을 소유하고, 부품은 상태 표현만 공유한다.

| prop | 용도 |
|---|---|
| `kind: "loading" \| "failed"` | 초기 상태 종류 |
| `message: string` | 상태별 한국어 안내. 로딩 문구는 반드시 “불러오고 있습니다.”로 끝낸다 |
| `onRetry: () => void` | 실패 재조회. 로딩에서는 호출되지 않는다 |
| `actions?: ReactNode` | 실패 복구 뒤의 선택적 흐름 이동 |

### 운영 현황 지표

- 준비 단계는 접수·참가자 게시 화면·현장 준비 확인을 먼저, 진행 단계는 조치 필요→입장 진행→최근 입퇴장을
  먼저 둔다. 종료·보관 단계는 마감 상태와 기존 마감 경로를 앞에 둔다. 기간별 신청·입장은 펼쳐 확인한다.
- `DRAFT`·`READY`는 신청 · 참가 확정 · 승인 대기를 하나의 압축 수치 행으로 읽고, 정원이 설정되면
  대기/정원을, 정원 0(제한 없음)이면 그 상태를 명시한다. 같은 크기의 네 지표 카드 그리드는 쓰지 않는다.
- `LIVE`·`ENDED`는 입장 진행 바를 중심에 둔다. 취소를 제외한 전체 등록 수가 분모이며, 눈에 보이는
  `입장/등록명 · 백분율`과 `role="progressbar"`의 `aria-label`·값을 함께 제공한다. 입장률 정의는
  결과 보고서와 같다. 확정자 중 미입장은 별도의 참가자 드릴다운으로 둔다.
- `ENDED`는 설문 응답·보고서 상태만 작은 보조 정보로 보여준다. `ARCHIVED`는 최종 요약이며 읽기 전용이다.
  참가자·보고서 상세 링크는 기존 목적지로 이동한다.
- 승인 대기는 필요할 때 처리 링크와 함께 안내하되 정상 미입장을 경보로 취급하지 않는다. 확인 배지는 셸의 행사 하위 메뉴와 연결하고,
  데스크·부스 설정은 현장 운영 화면에서 확인한다.

### 셸 메뉴 배지

- 현재 행사 `참가자` 메뉴는 `PENDING` 수, `메시지` 메뉴는 `FAILED`·`PARTIAL`·`NEEDS_CONNECTION`
  캠페인 수를 표시한다. 숫자·색·접근 가능한 이름(`승인 대기 N건`, `발송 확인 N건`)을 함께 쓴다.
- `AGENCY`·`MANAGER`에만 표시한다. 이것은 내비게이션의 표시 게이트일 뿐 서버 권한을 대체하지 않는다.
  `ENDED`·`ARCHIVED`에서는 승인 배지를 숨기고 메시지 배지는 유지한다. 대기가 있으면 참가자 링크가
  `?status=PENDING`으로 바로 들어간다. 메시지 배지는 `?attention=1`로 확인 대상 캠페인만 보여주고
  이력 섹션으로 이동한다. 이 화면에는 전체 캠페인으로 돌아가는 동작을 함께 둔다.
- 데스크톱 사이드바와 모바일 행사 메뉴는 같은 하위 메뉴 렌더 함수를 써 배지 규칙을 공유한다.

### 단계 이동과 새로고침

- 일반 단계 전환은 행사 설정에서 제공한다. 마감 문맥에서는 결과 안내 뒤 보관만 메시지 화면에서도
  같은 `StageTransitionConfirmation`과 기존 `event.stage` 커맨드로 처리한다. 행사 관리 권한·ENDED·접수 닫힘·
  열린 프로그램 없음 전제, 미저장/응답 미확인 경고와 같은 요청 재시도를 유지하며 자동 보관하지 않는다.
  인라인 확인, 전제조건 안내, 알 수 없는 단계·보관 단계의
  읽기 전용 처리를 유지하고, `event.stage` 커맨드의 응답이 불확실한 재시도는 같은 `commandId`를 쓴다.
  최종 권한·단계 판정은 계속 서버가 한다.
- 최근 입퇴장 새로고침은 20px SVG 아이콘과 44px 이상 버튼을 쓴다. `aria-label`·`title`은
  `새로고침`, 진행 중에는 `aria-busy`와 회전을 표시하고 `prefers-reduced-motion`에서는 회전을 끈다.
  “마지막 갱신 HH:MM”과 오류 복구의 “다시 불러오기”는 유지한다.

### 포토월과 행사 증빙 사진

- 참가자 포토월 게시물과 행사 증빙 원본은 목적·공개 범위가 다르므로 별도 화면/데이터로 보여준다.
  기존 프로그램 안의 참가자 사진은 검토 흐름을 유지하고 ZIP에는 승인된 사진만 포함한다.
- 행사 증빙 사진은 제안서의 고정 8개 분류를 선택하는 운영자 화면으로 관리한다. 데스크톱 구간 선택은
  테두리 카드 대신 수량과 활성 밑줄을 가진 한 줄 목록으로, 모바일은 수량이 포함된 기본 select와 한 줄
  사진 목록으로 전환한다. 업로드 영역은 현재 저장 구간을 분명히 밝히며 파일 선택과 드롭을 모두 제공한다.
  전송 전 썸네일·파일명·용량을 확인하고 전체 또는 개별 선택을 취소할 수 있다. 사진은 증빙 내용을
  크롭하지 않도록 contain으로 표시한다. ZIP 액션은 현재 섹션 제목 옆에 짧게 두고, 사진 관리 작업과
  완료 업로드 내역은 필요할 때 펼쳐 본다. ZIP은 선택한 섹션만 담는다.
- `AGENCY`와 해당 행사 MANAGER에게만 업로드·이동·보관함 제거 UI를 보인다. 제거는 보관함 참조만 빼며
  저장 파일 삭제나 기존 행사 파일 읽기 권한 회수가 아니라는 점을 확인 단계에서 설명한다. 서버 권한은 매 파일 요청·커맨드마다 판정한다.

### 목록·분석의 시각 위계

- 행사 카드의 D-day는 행사명과 진행 단계를 보조한다. 기본은 중립 표면·선·보조 글자 토큰으로 읽고,
  `오늘`·`내일`처럼 임박한 날짜만 기존 브랜드 채움을 사용한다. 날짜 계산·문구·배치는 바꾸지 않는다.
- 콘텐츠 카드의 제목 → 게시/고정/출력 배지 → 본문은 각각 `--s1`·`--s2` 눈금으로 묶는다.
  삭제는 일상적인 편집/게시와 구분되는 위험색 글자·테두리의 보조 버튼이며, 채운 주 버튼으로 강조하지 않는다.
  기존 인라인 확인 문법은 유지하되 확인 영역은 카드의 별도 전체 폭 행에 둔다. 공지·일정에 같은 규칙을 쓴다.
- 팀 구성원·초대의 이름은 굵은 본문, 역할은 작은 보조 글자로 구별한다. 이메일·담당 행사·만료는 줄을
  나누고 모두 보존한다. 긴 이메일을 생략 부호로 감추지 않는다.
- 결과 분석의 같은 수준 구역은 같은 바깥 간격을 사용하고, 구역 내부 제목·표는 더 가깝게 묶는다.
  숫자 열의 제목·값은 오른쪽 정렬과 `tabular-nums`로 비교하며 이름·종류 열은 왼쪽 정렬을 유지한다.
  모바일에서도 열을 생략하지 않고 기존 키보드 접근 가능한 표 스크롤을 보존한다.

### 업무별 적용 규칙

헤더와 섹션 머리 액션 슬롯에는 보조 스타일만 둔다. 화면의 핵심 작업을 슬롯 규칙에 맞추려고
보조화하지 않는다. 핵심 primary는 본문 작업 흐름에 남긴다. 운영 현황은 primary 0개를 유지한다.
행사 문맥 링크를 공통 프레임에 두고 중복된 하단·헤더 이동을 두지 않는다.
단계형 흐름(예: 참여 프로그램의 오류 복귀)은 필요한 복귀 목적지를 보존할 수 있다. 메타는 기존
부트스트랩 데이터만 읽고 API 계약을 확장하지 않는다.

- 행사 하위 페이지는 `h1=메뉴명`과 작은 행사 문맥·받은 메타를 공통 헤더에 둔다. 로딩·실패 중에도 메뉴 제목을 유지한다.
- 현장 운영은 데스크·전광판 출력·부스·스태프 배정·인증 방식·지도의 6개 섹션을 유지한다. 인증 방식·지도는
  현재 상태·미게시 초안을 요약하고 사전 설정을 펼친다. 앵커 직행과 미완료 입력의 복구는 해당 구역을 연다. 데스크·부스
  추가는 섹션 보조 액션이고 `스태프 배정` primary는 본문에서 유지한다. 지도 저장·전광판 적용 등
  기존 주 작업과 상태·전제조건도 그대로 둔다.
- 참여 프로그램은 프로그램 목록을 하나의 `ConsoleSection`으로 묶고, 편집/진행 상태와 데이터 잠금,
  추첨·Q&A 검증을 보존한다. 오류의 `행사 목록으로` 복귀와 `행사 설정` 보조 이동을 유지하되 운영
  현황 중복 이동은 제거한다.
- 경품은 목록을 섹션화하고 참가자 이동을 공통 헤더의 보조 액션으로 둔다. 기능 꺼짐, 지급·취소
  상태 gate와 기프티콘 모의 안내를 보존한다.
- 결과 보고서는 분석·보고서·조건부 상세의 3개 의미 섹션을 사용한다. 생성 primary와 스냅샷·공유
  잠금·후속 버전·JSON/인쇄는 본문에서 유지한다. 모바일 표는 모든 열을 보존하고, 필요할 때만
  가로 스크롤되는 키보드 포커스 영역 안에 둔다. 인쇄 산출물의 `EVENTOUCH · 결과 보고서` eyebrow는
  콘솔 장식이 아니라 출력물 내용이므로 유지한다. 인쇄는 선택한 저장 보고서의 복제만 출력하고 실시간 분석·다른 보고서는 포함하지 않는다.
- 설정은 기본 정보·참가 접수·기능·진행 단계·참가자 페이지 순서와 구역 바로가기를 보존한다.
  단계 확인·전제조건·불확실한 응답의 같은 `commandId` 재시도도 유지한다.
- 최상위 화면은 페이지명 `h1`만 사용하고 행사 메타·행사 뒤로가기를 두지 않는다. 콘솔 홈의
  `새 행사 만들기`는 primary로 유지하되 헤더 액션 슬롯 밖에 둔다. 행사 복제는 카드별 동작이
  아니라 만들기 대화상자 안의 `만들기 방식: 새 행사 / 기존 행사 복제`와 단계 표시 원본 선택으로
  처리한다(기본 새 행사 경로의 입력 즉시성은 유지, 입력 변경 전 확인·같은 복제 API·같은 복사 범위).
  전송 중이나 결과 미확인 영수증이 남은 동안에는 만들기 방식·원본 전환으로 재시도 정보를 지우지 않는다.
  행사 디렉터리 검색·단계/대기 필터는 도구막대에, 카드/달력 전환은 목록 섹션 머리에 둔다. 전체 수는 섹션 설명으로 읽고,
   조건이 있을 때만 초기화 행을 추가한다. 목록·달력·빈 상태는 같은 `ConsoleSection`에서 전환한다.
   이 목록의 짧은 결과 수는 제목 바로 아래의 요약으로 묶고, 카드/달력 전환은 그 묶음에 맞춰 가운데 정렬한다.
   다른 메뉴의 긴 섹션 설명·보조 행동 배치를 일괄 바꾸지 않는다.
- 고객사는 공통 도구막대의 등록과 공용 기록 행을 사용한다. 등록·업로드·삭제 확인과 AGENCY gate를 유지한다.
- 팀은 대기 초대·구성원·연동·최근 활동·로그인 보호를 구분한다. 초대/구성원 빈 상태를 실제 목록과
  분리하고, 조직 권한·1회 노출 링크·초대 회수·비밀번호 재설정·부분 읽기 전용 패널은 유지한다.
  공용 실패 재시도는 페이지와 셸을 함께 깨운다. bootstrap 실패를 빈 구성원 목록으로 오인하지 않는다.

**적용 범위:** 행사·고객사·팀, 행사별 운영 현황·참가자·가져오기·메시지·현장 운영·참여 프로그램·추첨/투표·
사진·콘텐츠·참가자 페이지 편집·경품·설정·보고서가 같은 프레임을 쓴다. 공개 행사·참가자 화면, 스태프, 전광판의
고유 프레임은 보존한다. 현재 빌드·렌더 검증 결과와 미검증 범위는 `docs/STATUS.md`에만 기록한다.
