# 조직 격리(멀티테넌시) 설계

Status: 공유형 SaaS·복수 운영사 소속·기존 자료의 단일 기존 운영사 귀속을 사용자 승인했다. 후속 격리 구현·검증을 진행하며 기존 운영 DB에는 적용하지 않았다. 현재 결과의 정본은 `docs/STATUS.md`다.
Related: `docs/ARCHITECTURE.md` 1절 목표, `docs/STATUS.md` 블로커.

## 구현 경계

- `server/tenancy.js`가 인증된 세션 선택·활성 소속·행사 소유권을 검증한다. 데이터 격리는 명시적 SQL 범위와 권한 검사로 집행하며 RLS를 사용한다고 주장하지 않는다.
- 마이그레이션은 원래 자료를 기존 운영사에 매핑한다. 계정 신원과 조직별 역할을 분리하며 `AGENCY`도 현재 운영사 범위만 접근한다.
- `memberships.write_permissions`는 서버의 명령별 허용표로 집행한다. 이는 행사 내 쓰기 범위이며 운영사 격리를 대신하지 않는다.
- 조직 없는 런타임 요청을 기존 운영사로 대입하지 않는다. 유일한 활성 소속의 초기 세션만 호환 선택하고, 명시 선택한 소속이 해제된 뒤 다른 소속으로 조용히 옮기지 않는다.

## 선택·재시도 프로토콜

- `GET /api/auth/organizations`는 소속 목록·활성 운영사·세션의 `contextVersion`을 반환한다. `/api/auth/me`의 역할도 선택한 운영사의 실효 역할이다.
- `POST /api/auth/organizations/select`는 `organizationId`, `commandId`, `expectedContextVersion`을 받는다. 여기서 문맥 버전은 세션별 선택 리비전이다.
- `POST /api/auth/organizations/:orgId/members/:accountId`의 `expectedContextVersion`은 **대상 구성원 행의 리비전**이다. 세션 선택 리비전과 다른 자원의 값이므로 이름이 같다고 서로 바꾸어 보내지 않는다. 생략한 역할 변경은 중지된 소속을 활성화하지 않는다.
- 조직 쓰기는 `x-eventouch-organization-id`와 `x-eventouch-context-version`을 함께 보낸다. 헤더가 현재 세션 선택을 덮어쓸 수 없다. 오래된 문맥은 `409 ORGANIZATION_CONTEXT_CHANGED`로 차단한다.
- 같은 선택 영수증은 다시 선택하지 않고 확인한다. 이후 다른 선택을 했다면 옛 요청을 재호출해도 현재 선택을 되돌리지 않는다.
- 선택된 문맥의 private GET 성공 응답에는 검증한 문맥 헤더를 붙인다. 미선택 신원·health·공개 행사·참가자 인증은 운영자의 선택 문맥이 아니다.
- 소속이 하나도 없는 정상 신원은 `403 NO_ORGANIZATION_MEMBERSHIP`로 안내한다. 소속 해제를 로그인 장애나 서버 오류로 표시하지 않는다.

## 설계 기준

1. **전역 계정과 조직 소속을 분리**한다. 계정은 로그인 식별자, 권한은 조직별 멤버십이 가진다.
2. **조직 컨텍스트는 인증된 멤버십에서만 유도**한다. 요청의 `orgId`를 신뢰하지 않는다.
3. **소유 범위**: `clients`·`events`(경유 자식 전부)·`invitations`·`staff_assignments`·`memberships`·파일·`command_receipts`·`message_outbox`·발송 설정. 자식은 소속 행사 경유로만 해석한다.
4. **공개 주소**: `events.slug`는 당분간 전역 유일 유지. `/event/:slug`가 모호해지지 않는다.
5. **멱등성 보존**: `command_receipts` 조회·재전송 범위를 조직·행사·주체로 좁히되, 키 충돌 의미를 바꾸지 않는다.

## 사용자 확정과 남은 운영 결정

- 공유형 SaaS, 계정의 복수 운영사 소속, 기존 계정 메뉴에서 조직 전환을 제공한다. 별도 조직 설정 메뉴는 만들지 않는다.
- 기존 자료는 기존 운영사 하나에 귀속한다. 원래 ID·관계·payload·티켓·체크인·영수증 결과·파일 경로와 바이트를 바꾸지 않는다.
- 조직별 역할·권한·활성 여부를 사용한다. 전역 계정의 역할을 다른 조직의 권한으로 사용하지 않는다.
- 표준적인 SaaS처럼 현재 운영사 소유자가 기존 팀 화면에서 소유자 초대와 역할 변경을 관리한다. 마지막 활성 소유자를 강등하거나 중지할 수 없고, 동시 변경에서도 소유자가 없는 운영사를 만들지 않는다. 역할만 바꾸는 요청은 중지된 소속을 자동 활성화하지 않는다.
- 선택 조직은 인증된 세션과 멤버십으로 결정하고 이전 탭의 오래된 문맥에서 온 쓰기를 거부한다. 이미 실행 중인 요청과 영수증은 처음 조직에 고정한다.
- RLS를 보조 방어로 쓰더라도 실제 접속 역할의 소유·SUPERUSER·BYPASSRLS를 확인한다. 검증하지 않은 SQL 격리를 보장한다고 서술하지 않는다.
- PII·인증 챌린지·감사 로그 보존 기간과 암호화·백업 정책.

## 이행 순서

1. 조직·조직 멤버십 스키마 추가(additive only), 기존 동작 불변.
2. 기존 데이터 매핑 감사(건수·관계·입장 토큰·체크인 이력 보존 확인).
3. 기존·새 읽기, 조직 REST, 커맨드 실행기, 파일·공개 투영·초대·발송 작업자를 모두 조직 범위로 묶고 교차 차단 행렬을 검증한다. 단일 조직 무제한 폴백을 남기지 않는다.
4. 제약·기본값 고정 → 재시작 유지·백업 복구 리허설 → 배포 승인.

## 검증 행렬 (롤아웃 게이트)

- 테넌트 A/B 읽기·쓰기·초대·재설정·파일·엑스포트·영수증·백그라운드 작업 교차 차단.
- 기존 데이터 마이그레이션 전후 ID·건수·관계·토큰·이력 동일.
- 관련 PostgreSQL 테스트는 직렬·격리 DB, 웹 빌드·타입·브라우저 흐름 통과.

## 운영 정책 경계

- 공유 계정의 비밀번호 재설정·전역 정지·잠금 해제는 다른 운영사에도 영향을 준다. 비활성 소속도 공유 판단에 포함한다. 조직 소유자의 권한을 전역 계정 관리로 확대하지 않으며 공유 보안 카운터·전역 IP 보호도 조직별 기록처럼 공개하지 않는다.
- 계정 보유자의 이메일 본인 인증과 셀프 복구는 조직 관리가 아닌 전역 신원 작업이다.
  본인이 사전에 인증한 주소만 사용하며 복구 시 모든 조직의 기존 세션을 무효화한다.
  기존 주소·초대 수락은 인증으로 보지 않고, 공유 계정에 대한 조직 소유자 재설정 금지는 유지한다.
- 기존 공급사 자격증명은 기존 운영사에만 귀속하며 새 운영사에 자동 상속하지 않는다. 실발송·발신자·비용 정책은 별도 확인한다.
- `EVENTOUCH_PUBLIC_URL`은 공통 공개 서비스 출처다. 비밀 발송 자격증명과 달리 전역 유일한 행사 slug의 티켓 링크에 재사용한다. 별도 운영사 도메인 설정은 추가하지 않는다.
- 개인정보·감사·백업 보존기간과 영구 삭제 정책은 미정이다. 검증을 위해 기존 영수증을 지우거나 기존 데이터·볼륨을 리셋하지 않는다.
