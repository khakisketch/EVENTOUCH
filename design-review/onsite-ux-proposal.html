현장·참여 재구성 제안

기획안의 게임·이벤트(퀴즈, 투표, 룰렛, 럭키번호, 사진, Q&A…)를 메뉴로 하나씩 늘리지 않고, "행사 전에 준비하고 → 당일 무대에서 진행하고 → 끝나면 결과·경품을 정리한다"는 실제 업무 흐름대로 화면을 다시 묶는 제안입니다. 화면 속 이름과 숫자는 모두 예시입니다.

1. 문제 진단 — 메뉴가 "데이터 종류"로 나뉘어 있고 "하는 일" 순서가 아님

지금은 무대에서 퀴즈 하나를 진행하려면 메뉴 4곳을 오가야 합니다. 운영자는 "지금 무대에서 뭘 하지?"를 생각하는데, 메뉴는 콘텐츠·추첨·경품·현장으로 쪼개져 있습니다.

퀴즈 만들기문항·정답·공개 시간행사 준비 › 참여 콘텐츠
→
행사장 화면에 띄우기전광판 출력 고르기현장·참여 › 현장 운영

근본 원인

  • 메뉴 = 데이터 종류: 콘텐츠·추첨·경품·사진이 각각 메뉴라, 이벤트 하나가 여러 메뉴에 흩어집니다.
  • 준비 화면과 진행 화면이 섞임: 당일 무대에서 써야 할 버튼(열기·마감·결과 공개·추첨)이 설정 화면 속에 묻혀 있습니다.
  • "현장 운영"이 잡동사니: 입장 데스크·부스·스태프 배정·전광판 출력이 한 화면에 있어 무엇을 하는 곳인지 이름만으로 알 수 없습니다.
  • 게임 종류가 늘수록 메뉴가 늘어나는 구조: 빙고·OX·스탬프를 더하면 또 메뉴가 생깁니다.

지향점

  • 게임은 "이벤트" 하나의 단위로 다룹니다. 종류는 메뉴가 아니라 템플릿입니다.
  • 이벤트마다 같은 생명주기: 준비 → 진행 → 결과 → 경품. 어느 종류든 같은 순서로 씁니다.
  • 당일에는 현장 모드(진행 전용 화면) 하나만 열어 두고 무대를 운영합니다.
  • 메뉴 이름은 하는 일로: "현장 운영" → "입장·스태프".

안 A큐시트(진행표) 중심

지적하신 대로 모든 목록 화면 위에 같은 카드 띠(참가자 명단의 4칸, 현장 운영의 2칸 등)가 있으면 눈에 들어오지도, 일에 도움이 되지도 않습니다. 큰 숫자·링은 운영 현황 · 현장 모드 · 결과 보고서에만 두고, 목록 화면은 개수가 붙은 상태 탭 한 줄로 줄여 바로 목록이 보이게 합니다.

적용 대상: 참가자 명단, 행사 목록, 메시지, 참여 이벤트, 고객사, 팀·권한, 경품, 사진. 앰버 개수(승인 대기·검토)는 그대로 눈에 띄게 남깁니다.

8. 진행 순서 제안 (결정해 주시면 바로 시작)

1단계 · 바로

메뉴 정리 + 공통 패턴

  • "현장 운영" → "입장·스태프", 전광판 출력은 현장 모드로 이동 준비
  • 목록 화면 카드 띠 → 개수 탭
  • 기간 분석을 결과 보고서 탭으로
2단계

"참여 이벤트" 통합 (안 B)

  • 참여 콘텐츠 + 추첨·투표를 한 목록·한 생명주기로
  • 템플릿 고르기 화면, 이벤트별 5단계
  • 경품 연결을 이벤트 안으로
3단계

현장 모드 (안 C)

  • 진행 순서 + 행사장 화면 + 큰 버튼 + 경품 지급
  • 태블릿 세로 대응
  • Q&A·사진 승인 큐

데이터 구조(콘텐츠·추첨·경품 기록)는 그대로 두고 화면과 메뉴만 다시 묶는 방식이라, 기존 기록과 권한·영수증 흐름은 바뀌지 않습니다. 스탬프 투어·빙고·OX 같은 새 게임 종류는 기능 추가라 별도 결정이 필요합니다.
